## Git basics (`shipyard-git`, spec `code`, T003 and T004)

Scope: `crates/shipyard-git` only. Not pushed.

### Decisions

- `git2` 0.21 with the `https` feature (the default `ssh` feature stays on). `project.rs` keeps the `git` command for clone and init, so a person's credential helpers apply there.
- One credentials place: `src/auth.rs`. `Auth` holds the stored credentials from `shipyard-secrets`. Each source answers once (stored, then the git credential helper, then the SSH agent), so a wrong token cannot loop. Proxy is `ProxyOptions::auto()`, defined once. Errors pass through `Auth::scrub`.
- A `Repo` is not `Sync`. Open one per call or per task.
- All numbers in the types are `u32` (specta cannot export 64-bit numbers). `time` is seconds since the epoch.
- A switch uses a safe checkout and names the blocking files (`GitError::DirtyTree`). A commit refuses while a merge or a rebase runs.
- `pull_rebase` refuses a dirty tracked file. A conflict aborts the rebase and the branch stays as it was. `push` never forces.
- A worktree removal refuses a dirty or untracked worktree unless `force`. It keeps the branch.

### Public API

`Repo::{open, discover, workdir, status, stage, unstage, diff_file, commit, log, commit_info, commit_files, commit_diff, branches, create_branch, switch_branch, fetch, pull_rebase, push, worktree_add, worktrees, worktree_remove}`, `Auth::{none, with, from_store}`, `GitError`.

### Open

- Discard (REQ-004), stash (REQ-006), conflict blocks (REQ-005), delete branch (REQ-013), remote head watch with change notice (REQ-015, REQ-017). The watch needs a per-fetch head compare in `shipyard-app`.
- No preemptive `Authorization` header (Legacy added one for Windows behind a corporate proxy that rewrites the 401 challenge). Add it in `auth.rs` if that case shows.
- Commits are not signed: libgit2 does not run GPG.
- Large files: above 8 MiB a file counts as binary in a diff.

## Refs and projects (`add-refs`, `add-projects`)

Scope: `add-refs` and `add-projects` (core, store, git `project.rs`, mcp `read_ref`, app commands, UI). Not pushed.

### Decisions

- Git: `shipyard-git/src/project.rs` runs the `git` command for clone, init and state, so a person's credential helpers apply. The connection token comes with `connections`; it goes through `auth.rs` of this crate.
- YAML: `serde_yaml` in `shipyard-store`. Core types (`ProjectFile`, health) derive `specta::Type` and keep no I/O.
- App data folder: `prefs.json`, `registry.json`, `refs/<project id>.sqlite`. Project id is the key in lower case (Q-014).
- Index update: no file watcher. Each refs query compares file stamps and re-reads changed files (REQ-004 holds, no manual action). `refs_reindex` repairs.
- Search: `LIKE`, not FTS. A ref match ranks first. Move to FTS when an index is large.
- A missing target is broken only for kinds that the repository files cover (adr, q, change, spec, wf, doc under scanned folders). Other kinds stay unresolved (Q-012).
- Commands are `async`, take `AppHandle`, return `Result<T, String>`. Logic sits in functions over `&AppState`. TypeScript reads results with `unwrap`.
- Layers: the shell feature cannot import another feature, so ref hooks are in `src/lib/refs/`, project hooks in `src/lib/projects/`, the shell context moved to `src/lib/shell/`. `BacklinkList`, `ProjectSwitcher` and `FindingRow` are molecules with gallery entries.
- Preferences and language load from the app data folder. The app waits for them before it renders (no theme flash).
- Accent override: a preset (`blue`, `violet`, `green`, `orange`, `rose`) sets `data-accent`. Tokens change the hue only.
- Clone: the picked folder is the parent. The clone goes in `<folder>/<repo name>` (spec REQ-003 updated).
- First run shows on Home / Inbox while no project is active. More projects open from the palette action "Open a local folder".

## Runners, providers and MCP (`shipyard-agents`, `shipyard-mcp`, spec `connections`, T009 to T012c)

Scope: `crates/shipyard-agents` and `crates/shipyard-mcp`. No Tauri command, no frontend. Not pushed.

### Decisions

- One owner for processes: `McpControl` in `shipyard-agents`. `shipyard-mcp` depends on it. The proxy (names, routing) and the relay (socket, stdio) hold no process.
- An MCP field is one keychain entry: `conn:<server>/<field>`. The secret reaches the child in its environment only. `McpConfig` (custom servers and enabled ids) holds no secret. The app saves it (REQ-013).
- A custom address must be `https` (or `http` on a local host) and holds no credential or query. It becomes `npx -y mcp-remote@latest <address>`.
- A dependency is the command that launches the server. Install uses Homebrew (macOS) or winget (Windows) only. No `sudo`, no remote script.
- Stop closes the child input, waits 300 ms, then kills. The app calls `stop_all` at quit.
- The relay socket is `0600` in a `0700` folder. A folder that others can use is refused.
- Tests use `sh` scripts (`shipyard_agents::fake`). They run on unix only.
- The Copilot fallback `gh copilot` is not carried. ACP launch arguments belong to the factory runner code.

### Public API (for the wiring worker)

- `runners::{detect, detect_in, Runner, RunnerState, ModelProvider}`. Provider: `new`, `models`, `test`, `chat`. The key is read from the store at `conn_account(id)`.
- `mcp_control::{McpControl, McpConfig, ServerDef, ServerRow, State, Dependency, CustomInput, catalogue, install_with, Os}`. `McpControl`: `new`, `list`, `set_enabled`, `add_custom`, `remove_custom`, `forget`, `set_field`, `start`, `stop`, `stop_all`, `state`, `request`, `config`, `install_dependency`. `start`, `request` and `install_dependency` block: call them in `spawn_blocking`.
- `mcp::proxy::{Proxy, split, SEP}`: `tools()` and `call(name, args)` for the endpoint, `forward` for the relay.
- `mcp::relay::{Relay, serve, FLAG}`: the app keeps a `Relay::listen(proxy, socket)`. The binary `shipyard --mcp-relay <id>` builds its own `McpControl` from the saved config and calls `serve`.
- Errors: `AgentError`. Types derive `Serialize`, not `specta`: map them in `shipyard-app`.

### Open

- Windows named pipe for the relay (T012c). Until then each Windows turn starts the server.
- The HTTP client reads for 30 s. A slow local model can fail the first chat. Needs a timeout option in `shipyard-http`.
- A stop does not kill the process group: a grandchild of `npx` can survive.
- `tools/list` reads the first page only.
- Non-secret fields (email, URL) are in the keychain too, and `ServerRow` gives only the keys that have a value.

## Git code operations, HTTP timeout, MCP group kill (worker 2, `shipyard-git`, `shipyard-http`, `shipyard-agents`)

Scope: those three crates and the `add-code` tasks file. No Tauri command, no frontend. Not pushed. `Cargo.lock`: only the `libc` line of `shipyard-agents` is mine.

### Public API (for the wiring worker)

- `shipyard_git::code::Repo`:
  - `discard(paths, untracked)`: unstaged edits go back to the staged content; a staged change stays. `untracked = true` deletes the untracked files under the paths. Ignored files never go. The match is literal (a file, or a folder and its content). The caller asks for the confirmation (REQ-004).
  - `stash_push(Option<&str>)`, `stash_list()`, `stash_apply(index)`, `stash_drop(index)`: `&mut self`, untracked files included. A conflict gives `GitError::Conflicts` and the stash stays. There is no `pop`: apply, then drop.
  - `conflicts()` gives `ConflictFile { path, text, segments }`. A segment is `Text` or `Block { ours, base, theirs }` (diff3). `text = false` means binary or a deleted side: use `resolve_side`.
  - `resolve_blocks(path, &[Choice])` (one choice per block: `Ours`, `Theirs`, `Both`, `Neither`), `resolve_side(path, Side)`, `mark_resolved(path)` (refuses with `GitError::ConflictMarkers` while a `<<<<<<<` or `>>>>>>>` line is left). Each one stages the file.
  - `delete_branch(name, force)`: refuses the working branch (`IsWorkingBranch`) and an unmerged one (`BranchNotMerged`) unless `force`. Local branches only: a forge-only branch is the forge adapter's job.
  - `remote_heads(remote)` and `head_changes(before, after)`: call the first before and after `fetch`. The second returns one `HeadChange { name, old, new, count, author, subject }` per moved tip. It is empty when nothing moved, so "behind with no new push" gives no notice.
- `shipyard_http::Request::timeout(Duration)`; `DEFAULT_READ_TIMEOUT` stays 30 s. `ModelProvider::chat` asks for 120 s. `models` and `test` keep the default.
- `McpControl::stop`, `stop_all` and the `Session` drop kill the process group on unix (`process_group(0)` at spawn, then `killpg`).

### Open

- Merge commit: `Repo::commit` refuses during a merge (`Busy`). Resolving conflicts stages the files, but the app cannot finish a merge yet.
- Block parsing assumes no marker-like line in the file text itself.
- Windows has no group kill (job object needed). The relay named pipe and the `tools/list` paging stay open.

## Connections: store, commands and Settings / Connections (T001, T002, T012a, T013 to T018)

Scope: `shipyard-core` (`work_item.rs`), `shipyard-app` (`connections.rs`, `commands/connections.rs`), the UI in `src/features/settings/connections/`, three molecules in `src/ui/molecules/`. Not pushed.

### Decisions

- The work item type, the flags and `TrackerKind::read_scope` live in `shipyard-core`. `Capabilities::require` returns the missing flag. `TrackerError` converts from it.
- `shipyard_app::connections::Connections` owns `connections.json` (app data folder), the keychain (`SecretStore`) and the HTTP client. A test uses `MemoryStore` and `FakeHttp`. `AppState.connections` is the system one.
- A connection has a `group` (tracker, forge) and a flat `kind`. `github`, `gitlab` and `azure-dev-ops` are valid in both groups. The id is a slug of the name.
- The view of a connection holds a `secret` flag, never the value. `connections_set_secret` is the only way in. The flag is stored: a list never reads the keychain.
- A draft goes through `trackers::connect` and `forges::connect` with an empty secret: the adapter rules (https, no credential in the address, Jira Cloud email) apply, no request goes out.
- A removal deletes the keychain entry first. A refused delete keeps the connection.
- `conn:<id>` resolves in `refs_resolve` from the store: title is the name, status is `<kind>: <state>`.
- The remove step lists the backlinks of `conn:<id>` from the ref index.
- `TestOutcome` and `Repository` derive `specta::Type`. `serde` and `specta` are new dependencies of `shipyard-http` and `shipyard-forges`.
- UI: `SecretInput`, `FlagList` and `ConnectionRow` are new molecules with gallery entries. The secret field shows a fixed mask as placeholder and its value stays empty. One primary action: Add, or Save while a form is open.
- Mock: `connectionsTest` fails for the secret `revoked` and for an address with `noscope`. The mock holds the secrets in `mockState().secrets`. No command returns them.

### Open

- Settings / Connections has trackers and forges only. The MCP, runner and provider groups wait for the wiring of `shipyard-agents` (T015 stays open). Add a value to `ConnectionGroup` and a group in `GROUPS`.
- `.shipyard/project.yaml` does not name the connection id (Q-018). The usage list reads the ref index, so a `conn:<id>` text in a repository file counts.
- The repository list reads the first 100 repositories. No "more" action. No create-remote action (REQ-019).
- A failure reason from an adapter is English. Only the frame is translated.
- The `secret` flag can drift if a person clears the keychain by hand. The test reads the keychain, so it still says "no secret saved". The row keeps the mask until the next edit.
- The clone token is still not wired into `shipyard_git::project::clone_repo`. `Connections::forge(id)` gives the adapter, `conn_account(id)` the keychain account.

## Code space, git part (`add-code`: Changes, History, Branches, commit, remote watch)

Scope: `shipyard-git` (merge commit, `Repo::remote`, clone credentials), `shipyard-core` (`code.rs`), `shipyard-app` (`commands/code.rs`, `Connections::git_auth`), `src/lib/code/`, `src/features/code/`, six molecules, one atom, one organism, the commit and sync actions of the status bar. Pull requests, Quality, Impacts and the terminal are W8 and are not built. Not pushed.

### Decisions

- `Repo::commit` finishes a merge: no conflict left, state `Merge`, parents are HEAD and each id of `MERGE_HEAD`, then `cleanup_state`. It re-reads the index first, so a merge made by the `git` command counts.
- `clone_repo(url, dest, &Auth)` now runs `git2` (`RepoBuilder`). The token never reaches a process argument, a URL or a log. A person's credential helper still applies through `Auth`.
- `Connections::git_auth(url)` gives the secret of the forge connection with the same host. Only an `https` address gets one. It serves clone, fetch, pull, push and the watch. No match gives `Auth::none()`.
- Commands are `code_*` in `commands/code.rs`. Logic is in plain functions over `&AppState`; tests sit in the same file (the module is private to the crate).
- `code_pull` is the sync action: a dirty working copy still fetches, then refuses and names the files. Clean: fast-forward or rebase (`pull --rebase`). It clears the watch notice.
- The watch is one thread in `setup`: every 15 minutes (fixed), it fetches each registered project that has a remote and compares heads before and after. A moved head stores a notice per project and emits `code-notice`. An offline project is skipped. `code_watch_notice` reads the stored notice; the status bar shows it beside Sync.
- Summary and branch name rules are pure functions in `shipyard-core::code`. The command returns their English text, which names the allowed types. The mock repeats the rules.
- The status bar holds the one commit action (a dialog with summary and description, a 50 character counter). It is off with nothing staged or with a conflict. `Action.disabled` also hides it from the palette.
- UI layers: hooks in `src/lib/code/` (the shell cannot import a feature). `FileRow`, `DiffView`, `CommitRow`, `ConflictBlock`, `Textarea` and `CommitDialog` are in `src/ui/` with gallery entries. `DiffView` is a molecule, not an organism.
- Changes: checkboxes select files and folders; each group has one action that acts on the checked files, or on all (Stage is the one primary action). Discard asks `confirmDialog` with the paths and the count.
- The mock keeps one in-memory working copy (`src/lib/ipc/mock-code.ts`). Tests set `mockState().code` to change it.

### Open

- `commit:` entities, backlinks and the links to `wi:` and `run:` (REQ-009, T007, T008).
- Delete of a forge-only branch (REQ-013). A forced delete of an unmerged local branch has no button.
- A per-project watch interval (Q-042). The `add-sync` tick does not run in the sync action yet (Q-041).
- The conflict view has no in-app file editor: a hand edit happens in another tool, then Mark resolved.
- Pull requests, Quality, Impacts, terminal and the file viewer (W8).
- Not run by hand: the Tauri webview (no desktop session). The watch thread and the event are covered by unit tests of the tick only.

## Wiring: agents, relay, shell items, project connection ids (T015, add-shell REQ-008, 012, 013, 014)

Scope: `shipyard-app` (`agents.rs`, `commands/agents.rs`, `commands/shell.rs`, `shell/`), `shipyard-mcp` (`relay::run_in`), `shipyard-cli`, UI in `src/features/settings/connections/`, `src/features/shell/`, `src/lib/{notifications,menus,updates}/`. Not pushed.

### Decisions

- `agents.json` in the app data folder holds the MCP config and the model providers (no secret). `Agents` owns `McpControl`, saves the config after each change and exposes `proxy`. The app calls `stop_all` on `RunEvent::Exit` and keeps a `Relay::listen` on `<data>/relay/mcp.sock` (unix).

- Provider ids are `provider-<slug>` so they never collide with a tracker or forge id in the keychain (`conn:<id>`).
- Specta renames: `McpServer`, `McpState`, `McpField`, `McpDependency` (the Rust names `State` and `Field` collide with other types).

- Context menus: `src/lib/menus` has the one table (kind to actions). A row passes handlers; an action with no handler is left out.
- Update check: `releaseUrl` preference (default the GitHub latest release API of this repository). It informs only.
- `.shipyard/project.yaml` accepts `connections: { tracker, forge }` (ids, validated as slugs). Settings / Project picks them. The remove step of a connection also lists the active project when it names the connection.
