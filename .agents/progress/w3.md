# W3 progress: connections backend (worker for trackers, forges, secrets)

Branch: `feat/core/foundation`. Scope: `shipyard-secrets`, `shipyard-http`, `shipyard-trackers`, `shipyard-forges`. Not pushed.

## Decisions

- Two new crates, picked up by the `crates/*` glob (no `Cargo.toml` edit): `shipyard-secrets` (Secret, keychain) and `shipyard-http` (client, fake, `TestOutcome`). Trackers and forges both need them, and `shipyard-agents` (providers, MCP) will too.
- Sync, not async: `ureq` 2 like Legacy. A Tauri command calls an adapter inside `spawn_blocking`.
- `rustls` has `default-features = false, features = ["ring", ...]`: the default adds `aws-lc-sys`, which needs cmake.
- The work item type is in `crates/shipyard-trackers/src/model.rs`. Core has no `work_item.rs` yet (T002). Move it, then re-export from the trackers crate.
- The Linear and Jira adapters share no code with GitHub or GitLab. A forge adapter shares nothing with a tracker adapter.
- `Cargo.lock` is not committed by this worker: another worker has uncommitted lock changes in the same file.
