### Public API for the engine worker

`shipyard_agents::runner`

- `runner(id) -> Option<Box<dyn Runner>>` for `claude`, `codex`, `copilot`, `gemini`, `opencode` (the ids of `runners::detect`).
- `start(&dyn Runner, RunSpec) -> Result<Run, AgentError>`. It checks the spec first and starts no process on an error.
- `RunSpec::new(prompt, dir)` then set: `model`, `effort`, `mode` (`Plan` or `Auto`), `allowed_tools`, `scratch` (a per-run folder outside the worktree), `mcp: Vec<McpEntry>`, `resume` (a session id from an earlier `Event::Session`), `vars` (child environment, secrets), `program`, `codex_home`.
- `McpEntry { name, command, args, vars }`: the Shipyard MCP server (stdio, `shipyard --mcp-relay`-like). `vars` hold secrets. They go to a `0600` file (or the ACP stdin), never to an argument. Claude Code sees the tools as `mcp__<name>__<tool>`: put those names in `allowed_tools`.
- `Run`: `recv()`, `recv_timeout(d) -> Recv::{Event, Idle, Done}`, `finish()`, `elapsed()`, `cancel()`, `cancel_handle() -> CancelHandle` (clone, send to the kill switch). Dropping a `Run` cancels it.
- `Event` (serde `{"type": ...}`): `Session { id }` (once, keep it), `Turn` (one per model call: count it for `max_turns`), `Text`, `ToolCall { id, name, input }`, `ToolResult { id, ok, output }`, `Usage { input_tokens, output_tokens, cached_tokens, cost_usd }` (sum all of them), `Error { message }`, `Exit { code, cancelled }` (always last).
- Limits stay with the engine: stall timeout is `recv_timeout` returning `Idle`; wall clock is `elapsed()`; turns are `Event::Turn`; the kill switch is `CancelHandle::cancel()` (kills the whole process group, the run then ends with `Exit { cancelled: true }`).
- `run_provider(provider, http, store, prompt) -> Run` runs an HTTP `ModelProvider` as a run (one `Turn`, `Text`, `Usage`, `Exit`). `ModelProvider::chat_full` gives text and tokens.
- Every `Text`, `ToolCall`, `ToolResult` and `Error` is scrubbed of each secret in `vars` and in the `McpEntry` vars. A non-JSON line of stdout is dropped. The stderr tail (2000 characters) becomes the `Error` of a non-zero exit when the stream named no error.
- The brief goes to the CLI on stdin from a `0600` file in `scratch` (Claude, Codex) or as the last argument (Gemini `--prompt=`, OpenCode after `--`). Copilot gets it over ACP.

`shipyard_git`

- `worktree::{child_path, child_name, child_branch}`: `<data>/worktrees/<project>/<run>/<child>`, name `<run>.<child>`, branch `shipyard/<run>/<child>`. Ids are plain (`[A-Za-z0-9_.-]`, not `.`-led or `-`-led), the run id has no dot.
- `Repo::child_worktree_add(data_dir, project, run, child, base)` (idempotent: the same child returns the same worktree), `child_worktree_remove(.., force)`, `run_worktrees_remove(data_dir, project, run, force)` (removes the clean children and fails with `WorktreeDirty(names)` for the dirty ones). The branch stays.
- `delivery::{is_tool_branch, PushMode}` and on `Repo`: `rename_branch(new) -> old` (refuses `BranchPublished` when the branch has an upstream), `rebase_onto(base) -> PullOutcome` (a conflict aborts and gives `Conflicts`), `commit_scope(paths, summary, description) -> sha` (HEAD plus those files only; refuses an AI attribution line and a bad summary with `BadSummary`), `push_run_branch(remote, base, PushMode::{Plain, ForceWithLease}, &Auth)` (refuses `ProtectedBranch` for the base, `main`, `master`, `develop`, `trunk` and `release/*`).
- The engine asks the approval before `ForceWithLease` (delivery REQ-015). A lease fails with `PushRejected("lease: ...")` when the remote branch moved since the last fetch: fetch, rebase and ask again.

`shipyard_forges`

- `connect_pull_api(config, secret, http) -> Box<dyn PullApi>`; `PullApi: Forge`, so one object does reads and writes.
- `find_pull(repo, branch) -> Option<PullRequest>` (open first), `create_pull(repo, &NewPull { title, body, source, target, draft })`, `mark_ready`, `labels`, `add_labels(repo, n, wanted) -> Labeled { applied, missing }` (existing labels only, case-insensitive, never create or remove), `add_reviewers`, `threads(repo, n) -> Vec<ReviewThread>`, `reply_thread`, `resolve_thread`, `status(repo, n) -> PullStatus { state, draft, ci, changes_requested, mergeable, head_sha }`.
- New `ForgeError::Rejected` (a refused write, a GraphQL error).

### Decisions

- A runner is `launch` (command) plus a `Parser` state machine. The same driver serves JSONL CLIs and the ACP JSON-RPC session (the parser writes the next lines and ends the run on the prompt response).
- The driver waits for the process, not for the pipe, and sweeps the group when the leader is gone. Reason: a launcher can fork a worker at the moment of a kill, and that worker held the pipe open (found by a flaky test).
- One process start at a time (a static lock). On macOS the standard library makes a pipe and marks it close-on-exec in two calls: a child that another thread starts between them keeps the pipe.
- `CancelHandle::cancel` kills nothing after the process was reaped (the id could belong to another process).
- Codex MCP goes in a profile file in the Codex home (`--profile shipyard-<scratch folder name>`), as Legacy does, and the file is removed at the end.
- GitHub threads use GraphQL (REST has no resolve). Azure DevOps has no label list: `labels` gives the labels in use on the last 100 pull requests. Azure reviewers must be identity ids (GUID).
- The git rename, rebase and commit rules reuse `shipyard_core::code::{check_branch_name, check_summary}` and `shipyard_core::delivery::is_tool_branch`.

### Open

- Not built: Codex `app-server` (exec only), a Windows process tree test (`taskkill` path is not run), `McpControl` spawns do not use the start lock.
- Not tried against real binaries: the Gemini flags (`--approval-mode`, `--allowed-tools`, `--resume`, `--prompt=`), the OpenCode event fields and the Copilot ACP option ids. The fakes follow the documented shapes and Legacy. Check them in the first manual run.
- Delivery REQ-012 assignee is not built (no `assign` call). Delivery REQ-018 needs the tail of a failed check log: `ci_status` gives names and URLs only.
- `labels` reads 10 pages of 100 labels (GitHub, GitLab).
- A force with lease is a read of the advertised refs, then the push, on two connections (the same client side check as git).
- `Cargo.lock`: no change from this work.

## Agent tools server (`shipyard-mcp`)

Scope: factory T016, T017 (REQ-016 to REQ-020, REQ-037). No engine logic, no Tauri command. Not pushed.
Legacy sources: `application/mcp/{rpc,stdio,legacy_server}.rs` (JSON-RPC methods, version negotiation, tool result shape, Host and Origin guard, close without reset, connection cap).

### API for the engine and the app

`shipyard_mcp::tools::agent`

- `trait AgentEvents: Send + Sync { fn emit(&self, who: &Binding, event: AgentEvent) -> Result<Value, String>; }`. The engine implements it. `Ok` goes to the agent as structured content (a value that is not an object becomes `{"result": v}`). `Err` is a message for the agent (`isError`).
- `enum AgentEvent { AskQuestion, PostProgress, Handoff, Message, SpawnSubtask, Report, ReadTicket, ReadRef }`, `event.tool()`. Payloads: `AskQuestion { question, options (2 to 4), recommended (from 1), free_text, kind: Ticket | Spec, spec }`, `PostProgress { text }`, `Handoff { role, summary, step }`, `Message { to: step id | "person", text }`, `SpawnSubtask { title, brief, role }`, `Report { outcome: Done | Partial | Failed, summary, refs, output }`, `ReadTicket { reference }`, `ReadRef { reference }`.
- The server checks the shape. The engine decides the rest: the run state of `ask_question` (`RunEvent::Ask`), the `for_each` and `max_parallel` limit of `spawn_subtask`, the target step of `handoff` and `message`, the step end of `report`, the ticket mirror for `read_ticket`. An unknown ref must be `Err` (REQ-020). `tools::read_ref::read_ref` returns an unresolved result: map it to `Err` in the engine.
- `report.output` carries the fields that the next steps read, such as `tasks` for `for_each: plan.tasks`.

`shipyard_mcp::session`

- `Sessions::open(Binding { run, step, tools }) -> (token, Arc<Session>)`: open one for each step that starts an agent. `tools` is the `tools` field of the step. The token has 256 random bits (hex). `resolve(token)`, `revoke_run(run)` (call it when the run or the step ends).
- Put the token in the `McpEntry` vars (`SHIPYARD_MCP_TOKEN`, `transport::TOKEN_ENV`) or in the HTTP header of the MCP config file. Never in an argument.

`shipyard_mcp::server`

- `Server::new(Arc<dyn AgentEvents>)`, `.with_proxy(Arc<Proxy>)` (adds the proxied tools to `tools/list` and routes `<server>__<tool>` calls), `.with_limits(Limits)`, `.with_clock(..)` (tests). `server.sessions()`. `server.handle(token, &request) -> Option<Value>` (`None` for a notification).
- `Limits` defaults: 60 calls per minute for each session, 64 KiB per call, 32 KiB per report, 256 KiB per answer.
- Methods: `initialize`, `ping`, `tools/list`, `tools/call`, `resources/list` (empty), `resources/templates/list`, `resources/read` for `shipyard://ref/<percent-encoded ref>` (it is a `read_ref` call).
- A step lists and calls only its tools. A proxied tool is not filtered here: the runner `allowed_tools` does it.

`shipyard_mcp::transport`

- `Http::start(Arc<Server>, port) -> io::Result<Http>` (`127.0.0.1` only, port 0 picks one; `port()`, `url()`; drop stops it). Needs `Authorization: Bearer <token>`, a local `Host` for the bound port, no foreign `Origin`. `401` bad token, `403` bad Host or Origin, `404` path, `405` method, `413` body over 1 MiB, `202` notification.
- `serve_stdio(&Server, token, BufRead, Write)`.

### Decisions to confirm

- `handoff` takes `role` and `summary` (REQ-019) plus an optional `step`. `message` takes `to` as a step id or `person`: there is no run-wide target.
- `ask_question.kind` is `ticket` (default) or `spec`: a spec question needs a `spec:` ref, a ticket question refuses one. The engine creates the RAID file only for `spec` (questions-loop REQ-007).
- A refused call is a tool result with `isError`, so the agent reads the reason. Only an unknown method or resource is a JSON-RPC error. A bad token is `-32001`.
- The input schema is a small own checker (`schema.rs`), not the `jsonschema` crate.

### Open

- `shipyard --mcp` does not exist: a stdio server in the agent process cannot reach the engine. Add a bridge that reads `SHIPYARD_MCP_URL` and the token from env and forwards each line to `Http`, or give agents the HTTP entry directly. `McpEntry` is a command entry today.
- Nothing starts `Http` or implements `AgentEvents` yet (engine T009, app T018).
- The rate and size limits are server wide defaults. A step cannot set its own yet.
- Proxied tools count against the rate limit but pass no step filter.

## MCP bridge and the Shipyard entry of a run (`shipyard-cli`, `shipyard-agents`)

Scope: factory T017b, T017c (REQ-037). Closes the first open item of the agent tools section. Not pushed.

### API for the engine and the app

- `shipyard --mcp-bridge` (`shipyard-cli/src/bridge.rs`): a stdio MCP server. It reads `SHIPYARD_MCP_URL` and `SHIPYARD_MCP_TOKEN` from the environment (never from arguments), posts each line to the URL with `Authorization: Bearer`, and writes the answer as one line. It refuses a URL that is not `http://127.0.0.1` or `http://localhost` before it reads a line. Missing variable: exit 1 with a message. App closed, bad token or any HTTP error: a JSON-RPC error with the request id (code `-32000`, no token in the text). A notification gets no output.
- `McpEntry::shipyard(&dyn Runner, exe, url, &Secret) -> Result<McpEntry, AgentError>` (`shipyard_agents::runner`): the `shipyard` entry of a run. `Runner::http_mcp()` chooses per runner: `true` for Claude Code (`McpEntry.http = Some(HttpEntry { url, headers })`, written as `type: http` with an `Authorization` header), `false` for Codex, Gemini, OpenCode and Copilot (command entry: `exe --mcp-bridge`, the two variables in `vars`). The files stay `0600`. `start` refuses an HTTP entry for a runner that takes none, and starts no process.
- `McpEntry` has a new field `http: Option<HttpEntry>`. Set `http: None` in a literal.
- The app passes `exe` (its own `shipyard` binary path), `Http::url()` and the token of `Sessions::open`. Put `mcp__shipyard__<tool>` names in `allowed_tools`.
- Constants `BRIDGE_FLAG`, `URL_ENV`, `TOKEN_ENV` in `shipyard_agents::runner`. The CLI repeats the same three strings (`shipyard-agents` is not a dependency of `shipyard-cli`: no `Cargo.lock` change beyond `serde_json`).

### Decisions to confirm

- Claude Code takes the HTTP entry because it supports `type: http` with headers. The bridge serves the others. Gemini CLI also supports HTTP; it stays on the bridge until a manual run shows the format.
- The bridge opens one connection for each message (the server closes each one). Keep-alive is not built.
- The bearer value and the bare token are both scrubbed from events.

### Open

- Not run against the real Claude Code or the real app: tests use fake CLIs and a fake endpoint. Check the `type: http` entry and the bridge in the first manual run.
- Nothing starts `Http` or builds the entry yet (engine T009, app T018).
- The bridge has no Windows-specific test (std sockets only).

### Behavior

- Join (`children.rs`): after the last child of a `workspace: worktree` step, each child is merged in order. A conflict or error: `Blocked`, event `{"blocked": "merge conflict: child <id>: <files>"}`, worktrees kept. After `unblock` the pump joins the rest. When all are joined, the child worktrees go.
- Review (`review.rs`): the brief has the base, head, ticket, specs at the base commit, the checklist and the diff. It has no output of a builder and no CLI session. `output.findings` is checked: each cited line is opened with `Git::line`; a bad one is dropped and logged. P0 and P1 block, P2 is only logged. Gates (`Project.gates`) run when the review does not block and the workflow has an `open_pr` step. A red gate is a P1 finding. A report with no `findings` list keeps the old outcome rule.
- Pull request (`pull_request.rs`): base (declared, `develop`, default; never `release*`), rename a tool branch, find the pull request, commit the uncommitted files with `<type>(<area>): <title>`, rebase, push (`Write::Push`), open a draft. Each stage reads the real state first, so a retry or a click goes on from where the run is. No reviewer, a rename refusal, a conflict, a release base or no changed file: `Blocked` with the reason. A forge read that fails: the step fails with its retries.
- Feedback (`feedback.rs`): CI failure and review changes go `PROpen`, `ChangesRequested`, `Working`. The builders, the review and the pull request step run again with the notes (check names, URLs and tails, open threads). A push after a rewrite is a force with lease and always waits. After the push, one `ResolveThreads` write replies with the fixing commit. At `max_turns` the run fails. A feedback that arrives while the run is blocked or paused waits for the click or the resume. A closed pull request blocks the run (any active state).
- Close (`merge.rs`): merge event, `Merged`, summary comment once (switch or approval), worktree removal, `Done` in the same step. The ticket move is the state map move of `Merged`, with no move for a ticket that the mirror shows as closed. A write that waits for a click does not hold the run.

### Decisions to confirm

- The run reaches `Done` at once after the merge, as the plan says. The earlier note "a rejected ticket move after the merge can block the run" no longer holds: a rejection after `Done` only drops the write.
- A feedback round runs all the builders and the review again (the same rule as a fix round) and gives the review a new count of fix rounds.
- `gates` run only in a workflow that opens a pull request.

### Open

- No squash of a child branch into the run folder in `shipyard-git`: the `Git::merge_child` adapter needs it (apply the diff from the merge base to the child tip to the working copy).
- The `reviewers` key of `automation.yaml` is not in the codec (the engine takes `Project.reviewers`). The assignee (REQ-012) and the impacts digest (REQ-027) have no port.
- `PullApi` gives no log tail: `FailedCheck.tail` stays `None` until an adapter reads the log.

- Run state is still in memory: the retry after a restart finds the pull request on the forge, but the run itself is lost.
- Not checked against a real repository or forge: the ports are tested with fakes only.

### Behavior

- Restart (`persist.rs`). Each public call saves the runs that it changed (`Guard`, on drop): the run record, steps, questions, the approvals of the run. A `meta` save holds the run id counter, the approval counter and the global kill switch. At the start each run is read back. A step that ran goes back to `Pending` and keeps its session: the pump resumes it on the session, or briefs it again with no session. A run in `Merged` closes. A run in the log with no save and no end is named in `take_errors` (not guessed). Each live run gets a `note` event `restart`.
- Idempotency. A write logs `sending` (key), then `sent` (key, made). At the start the writes after the last save of a run are kept in memory. The same write made again is taken as done (`replayed`, its `made` id applies as if it was sent). A comment or thread reply with `sending` and no `sent` is not sent again (at most once) and a `note` says so. The other writes are safe to repeat (a state setter, a push, the pull request step finds the pull request first).
- `message` to a step: a note in the step. A running target stops after its turn and starts again with the text, on its session (the CLI takes no line in the middle of a turn). A target that has not started gets the note in its brief. A step that ended, a missing step and the caller itself are errors.
- `handoff`: the caller ends (`Done`, the summary is its output) and the step of the role gets the summary as a note. The step is the one named, else the first step with the role that has not ended. A role mismatch, an ended step and the caller itself are errors.
- `spawn_subtask`: a new child of the calling step. The step needs `for_each` and `workspace: worktree`, the role must exist, the children that run now stay under `max_parallel`, and the run budget stays under 80 %. The workflow `max_turns` bounds the rest. The child has `item = {title, brief}` and its own role.
- `read_ref`: reads the ref index. A broken or unresolved ref and text that is not a ref are errors (REQ-020). No index: an error.
- A merge in a fix round: the agents stop (`park`), `Merged`, the close, `Done`. A push, pull request or thread reply approval of the run is dropped.

### Done

1. Slow work outside the lock. `Guard` (the lock) now runs the jobs of a change when it goes: phase one queues a `Job` (a gate, or a tracker, forge or push write) under the lock; the jobs run with no lock, one thread for each run, in order inside a run; phase two locks again and applies each result. A fact that went out (comment id, pull request) is always recorded; a decision that follows (next pull request stage, gate verdict) only when the run did not change (`gens`, bumped by each transition). A dropped gate verdict leaves `StepRec::gating`, and the next pump runs the gate again (this also covers a restart). `pump_run` skips a run whose gate is out; `advance_pr` skips a run whose push or pull request is out. Public calls (`write`, `approve`) wait for their own job and return the made id. `shutdown` sets `closing`: a gate that the exit stopped gives no verdict.
2. Gate timeout. The shell leads its own process group (`process_group(0)`); a timeout kills the group (`runner::kill_group`, Windows `taskkill /T`). `delivery::kill_gates` kills the live gate groups at exit.
3. One ref index for each project (`Project.refs`, `AppState::index_of`). `read_ref` reads the index of `run.project`. The loop reindexes each project with an active run (`reindex_repo`; mirror entries stay for the active project only).
4. `read_ref` takes the index under a short factory lock, then queries with no factory lock. Partial: no "new index and swap" during a rescan. A rescan is incremental and holds only the index of one project, so it delays that agent call and holds no view. Swap if a scan proves slow.
5. Duplicate run: the check is in `Inner::start`, under the lock. The app pre-check is gone.
6. An answer in the Inbox posts `<!-- shipyard:a Q-NNN -->` with the chosen option or text at once (the click is the consent, whatever the switch says). The id is stored (`question_posted`); `pickup::answers` returns none for it and keeps the latest question marker. A question comment still in the queue is replaced by one comment with question and answer. No comments on the tracker: a note in the run log.
7. Run log fallback: one scratch file in the temp folder with two connections. `run_log_degraded` (`Option<String>`) says why. The bindings and the mock have it. Not one shared connection: the engine owns its `RunLog` by value.
8. `OpenPr` checks the run folder branch and refuses `branch == base`.
9. The start removes `<app data>/agents/<run>` for each run that is not live.
10. The loop compares the name, size and mtime of `.shipyard/workflows` and `.shipyard/roles` once each second and calls `ensure` on a change. No `notify` crate in the tree.

### Open

- Two threads that call `pump` meanwhile: the one that holds a gate job blocks in its own call (not in the lock). The app loop therefore waits for a gate of 15 min at most, as before, but views, tools, sync and exit do not.
- A comment that went out and whose id is stored a moment later can be read by a tick in between as a late reply (logged, no effect).
- `check_findings` (`git.line`), `base_of`, `try_pr` reads and `merge_child` still run under the lock; they are short local or read calls. Move them the same way if one proves slow.
