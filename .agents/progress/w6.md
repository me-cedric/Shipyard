### Public API for the engine worker

`shipyard_store::run_log` (SQLite file in the app data folder, for example `runs.sqlite`)

- `RunLog::open(path)`, `open_memory()`. A layout that this build does not know is an error, never a reset.
- `append(run, step: Option<&str>, kind, &serde_json::Value, ts) -> id`. `ts` is Unix ms from the engine clock: the store never reads a clock. `run` is the ULID of `run:<ulid>` and must not be empty.
- Reads: `run(run)`, `since(id, limit)` (the tail), `last(run, kind)` (use it for the run state after a restart), `runs()`, `cites(target)` (runs whose payload holds the exact string, for `pr:`, `wi:`, `q:` backlinks).
- No update and no delete exist. SQL triggers refuse both. A log event has `id, run, step, kind, payload, ts`.
- `run_log::kind`: `STATE`, `TOOL`, `RUNNER`, `WRITE`, `NOTE`, `PR`. Any other text is allowed. Suggested payloads: `STATE` `{"from","to","event"}`; log each `Refused` and each late answer or edit as `NOTE`.

`shipyard_store::factory_files`

- `seed(root)`: writes the five workflows and seven roles into `.shipyard/workflows/` and `.shipyard/roles/`, per directory, only when the directory is missing. Call it on the first use of a project.
- `load(root, &last: &Loaded) -> Loaded { workflows: BTreeMap<id, Workflow>, roles: BTreeMap<name, Role>, issues: Vec<FileIssue{file, line, message}> }`. An invalid file keeps its version from `last` and adds an issue. Call it again when the watcher fires. `Loaded::role(name)` falls back to the bundled profile.
- `Role { id, description, model, effort, prompt }`. `parse_workflow`, `parse_role`, `default_workflows()`, `default_roles()`.
- Models are tiers `top`, `mid`, `small`. **The engine and `connections` must map each tier to a model of each runner in config.** Nothing maps them yet. A step's `model` and `effort` win over the role profile.
- `feature` runs `grill` (skill `grill-me`), `plan` (`gate: human`, `mode: plan`), `build` (`for_each: plan.tasks`, `max_parallel: 2`, `workspace: worktree`), `review` (`fresh_context`, `max_rounds: 2`), `pr` (`open_pr`). The planner prompt tells the agent to return the list `tasks` in its report. Tool names in `tools:` are the eight MCP tools.

`shipyard_store::automation_file` (extends the sync codec)

### Public API for the engine worker

`shipyard_agents::runner`

- `runner(id) -> Option<Box<dyn Runner>>` for `claude`, `codex`, `copilot`, `gemini`, `opencode` (the ids of `runners::detect`).
- `start(&dyn Runner, RunSpec) -> Result<Run, AgentError>`. It checks the spec first and starts no process on an error.
- `RunSpec::new(prompt, dir)` then set: `model`, `effort`, `mode` (`Plan` or `Auto`), `allowed_tools`, `scratch` (a per-run folder outside the worktree), `mcp: Vec<McpEntry>`, `resume` (a session id from an earlier `Event::Session`), `vars` (child environment, secrets), `program`, `codex_home`.
- `McpEntry { name, command, args, vars }`: the Shipyard MCP server (stdio, `shipyard --mcp-relay`-like). `vars` hold secrets. They go to a `0600` file (or the ACP stdin), never to an argument. Claude Code sees the tools as `mcp__<name>__<tool>`: put those names in `allowed_tools`.
- `Run`: `recv()`, `recv_timeout(d) -> Recv::{Event, Idle, Done}`, `finish()`, `elapsed()`, `cancel()`, `cancel_handle() -> CancelHandle` (clone, send to the kill switch). Dropping a `Run` cancels it.
- `Event` (serde `{"type": ...}`): `Session { id }` (once, keep it), `Turn` (one per model call: count it for `max_turns`), `Text`, `ToolCall { id, name, input }`, `ToolResult { id, ok, output }`, `Usage { input_tokens, output_tokens, cached_tokens, cost_usd }` (sum all of them), `Error { message }`, `Exit { code, cancelled }` (always last).
- Limits stay with the engine: stall timeout is `recv_timeout` returning `Idle`; wall clock is `elapsed()`; turns are `Event::Turn`; the kill switch is `CancelHandle::cancel()` (kills the whole process group, the run then ends with `Exit { cancelled: true }`).
- `run_provider(provider, http, store, prompt) -> Run` runs an HTTP `ModelProvider` as a run (one `Turn`, `Text`, `Usage`, `Exit`). `ModelProvider::chat_full` gives text and tokens.
- Every `Text`, `ToolCall`, `ToolResult` and `Error` is scrubbed of each secret in `vars` and in the `McpEntry` vars. A non-JSON line of stdout is dropped. The stderr tail (2000 characters) becomes the `Error` of a non-zero exit when the stream named no error.
- The brief goes to the CLI on stdin from a `0600` file in `scratch` (Claude, Codex) or as the last argument (Gemini `--prompt=`, OpenCode after `--`). Copilot gets it over ACP.

`shipyard_git`

- `worktree::{child_path, child_name, child_branch}`: `<data>/worktrees/<project>/<run>/<child>`, name `<run>.<child>`, branch `shipyard/<run>/<child>`. Ids are plain (`[A-Za-z0-9_.-]`, not `.`-led or `-`-led), the run id has no dot.
- `Repo::child_worktree_add(data_dir, project, run, child, base)` (idempotent: the same child returns the same worktree), `child_worktree_remove(.., force)`, `run_worktrees_remove(data_dir, project, run, force)` (removes the clean children and fails with `WorktreeDirty(names)` for the dirty ones). The branch stays.
- `delivery::{is_tool_branch, PushMode}` and on `Repo`: `rename_branch(new) -> old` (refuses `BranchPublished` when the branch has an upstream), `rebase_onto(base) -> PullOutcome` (a conflict aborts and gives `Conflicts`), `commit_scope(paths, summary, description) -> sha` (HEAD plus those files only; refuses an AI attribution line and a bad summary with `BadSummary`), `push_run_branch(remote, base, PushMode::{Plain, ForceWithLease}, &Auth)` (refuses `ProtectedBranch` for the base, `main`, `master`, `develop`, `trunk` and `release/*`).
- The engine asks the approval before `ForceWithLease` (delivery REQ-015). A lease fails with `PushRejected("lease: ...")` when the remote branch moved since the last fetch: fetch, rebase and ask again.

`shipyard_forges`

- `connect_pull_api(config, secret, http) -> Box<dyn PullApi>`; `PullApi: Forge`, so one object does reads and writes.
- `find_pull(repo, branch) -> Option<PullRequest>` (open first), `create_pull(repo, &NewPull { title, body, source, target, draft })`, `mark_ready`, `labels`, `add_labels(repo, n, wanted) -> Labeled { applied, missing }` (existing labels only, case-insensitive, never create or remove), `add_reviewers`, `threads(repo, n) -> Vec<ReviewThread>`, `reply_thread`, `resolve_thread`, `status(repo, n) -> PullStatus { state, draft, ci, changes_requested, mergeable, head_sha }`.
- New `ForgeError::Rejected` (a refused write, a GraphQL error).

### Decisions

- A runner is `launch` (command) plus a `Parser` state machine. The same driver serves JSONL CLIs and the ACP JSON-RPC session (the parser writes the next lines and ends the run on the prompt response).
- The driver waits for the process, not for the pipe, and sweeps the group when the leader is gone. Reason: a launcher can fork a worker at the moment of a kill, and that worker held the pipe open (found by a flaky test).
- One process start at a time (a static lock). On macOS the standard library makes a pipe and marks it close-on-exec in two calls: a child that another thread starts between them keeps the pipe.
- `CancelHandle::cancel` kills nothing after the process was reaped (the id could belong to another process).
- Codex MCP goes in a profile file in the Codex home (`--profile shipyard-<scratch folder name>`), as Legacy does, and the file is removed at the end.
- GitHub threads use GraphQL (REST has no resolve). Azure DevOps has no label list: `labels` gives the labels in use on the last 100 pull requests. Azure reviewers must be identity ids (GUID).
- The git rename, rebase and commit rules reuse `shipyard_core::code::{check_branch_name, check_summary}` and `shipyard_core::delivery::is_tool_branch`.

### Open

- Not built: Codex `app-server` (exec only), a Windows process tree test (`taskkill` path is not run), `McpControl` spawns do not use the start lock.
- Not tried against real binaries: the Gemini flags (`--approval-mode`, `--allowed-tools`, `--resume`, `--prompt=`), the OpenCode event fields and the Copilot ACP option ids. The fakes follow the documented shapes and Legacy. Check them in the first manual run.
- Delivery REQ-012 assignee is not built (no `assign` call). Delivery REQ-018 needs the tail of a failed check log: `ci_status` gives names and URLs only.
- `labels` reads 10 pages of 100 labels (GitHub, GitLab).
- A force with lease is a read of the advertised refs, then the push, on two connections (the same client side check as git).
- `Cargo.lock`: no change from this work.

## Agent tools server (`shipyard-mcp`)

Scope: factory T016, T017 (REQ-016 to REQ-020, REQ-037). No engine logic, no Tauri command. Not pushed.
Legacy sources: `application/mcp/{rpc,stdio,legacy_server}.rs` (JSON-RPC methods, version negotiation, tool result shape, Host and Origin guard, close without reset, connection cap).

### API for the engine and the app

`shipyard_mcp::tools::agent`

- `trait AgentEvents: Send + Sync { fn emit(&self, who: &Binding, event: AgentEvent) -> Result<Value, String>; }`. The engine implements it. `Ok` goes to the agent as structured content (a value that is not an object becomes `{"result": v}`). `Err` is a message for the agent (`isError`).
- `enum AgentEvent { AskQuestion, PostProgress, Handoff, Message, SpawnSubtask, Report, ReadTicket, ReadRef }`, `event.tool()`. Payloads: `AskQuestion { question, options (2 to 4), recommended (from 1), free_text, kind: Ticket | Spec, spec }`, `PostProgress { text }`, `Handoff { role, summary, step }`, `Message { to: step id | "person", text }`, `SpawnSubtask { title, brief, role }`, `Report { outcome: Done | Partial | Failed, summary, refs, output }`, `ReadTicket { reference }`, `ReadRef { reference }`.
- The server checks the shape. The engine decides the rest: the run state of `ask_question` (`RunEvent::Ask`), the `for_each` and `max_parallel` limit of `spawn_subtask`, the target step of `handoff` and `message`, the step end of `report`, the ticket mirror for `read_ticket`. An unknown ref must be `Err` (REQ-020). `tools::read_ref::read_ref` returns an unresolved result: map it to `Err` in the engine.
- `report.output` carries the fields that the next steps read, such as `tasks` for `for_each: plan.tasks`.

`shipyard_mcp::session`

- `Sessions::open(Binding { run, step, tools }) -> (token, Arc<Session>)`: open one for each step that starts an agent. `tools` is the `tools` field of the step. The token has 256 random bits (hex). `resolve(token)`, `revoke_run(run)` (call it when the run or the step ends).
- Put the token in the `McpEntry` vars (`SHIPYARD_MCP_TOKEN`, `transport::TOKEN_ENV`) or in the HTTP header of the MCP config file. Never in an argument.

`shipyard_mcp::server`

- `Server::new(Arc<dyn AgentEvents>)`, `.with_proxy(Arc<Proxy>)` (adds the proxied tools to `tools/list` and routes `<server>__<tool>` calls), `.with_limits(Limits)`, `.with_clock(..)` (tests). `server.sessions()`. `server.handle(token, &request) -> Option<Value>` (`None` for a notification).
- `Limits` defaults: 60 calls per minute for each session, 64 KiB per call, 32 KiB per report, 256 KiB per answer.
- Methods: `initialize`, `ping`, `tools/list`, `tools/call`, `resources/list` (empty), `resources/templates/list`, `resources/read` for `shipyard://ref/<percent-encoded ref>` (it is a `read_ref` call).
- A step lists and calls only its tools. A proxied tool is not filtered here: the runner `allowed_tools` does it.

`shipyard_mcp::transport`

- `Http::start(Arc<Server>, port) -> io::Result<Http>` (`127.0.0.1` only, port 0 picks one; `port()`, `url()`; drop stops it). Needs `Authorization: Bearer <token>`, a local `Host` for the bound port, no foreign `Origin`. `401` bad token, `403` bad Host or Origin, `404` path, `405` method, `413` body over 1 MiB, `202` notification.
- `serve_stdio(&Server, token, BufRead, Write)`.

### Decisions to confirm

- `handoff` takes `role` and `summary` (REQ-019) plus an optional `step`. `message` takes `to` as a step id or `person`: there is no run-wide target.
- `ask_question.kind` is `ticket` (default) or `spec`: a spec question needs a `spec:` ref, a ticket question refuses one. The engine creates the RAID file only for `spec` (questions-loop REQ-007).
- A refused call is a tool result with `isError`, so the agent reads the reason. Only an unknown method or resource is a JSON-RPC error. A bad token is `-32001`.
- The input schema is a small own checker (`schema.rs`), not the `jsonschema` crate.

### Open

- `shipyard --mcp` does not exist: a stdio server in the agent process cannot reach the engine. Add a bridge that reads `SHIPYARD_MCP_URL` and the token from env and forwards each line to `Http`, or give agents the HTTP entry directly. `McpEntry` is a command entry today.
- Nothing starts `Http` or implements `AgentEvents` yet (engine T009, app T018).
- The rate and size limits are server wide defaults. A step cannot set its own yet.
- Proxied tools count against the rate limit but pass no step filter.
