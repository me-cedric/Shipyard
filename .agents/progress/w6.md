### Public API for the store and engine workers

`shipyard_core::run`

- `RunState` now derives `Serialize`, `Deserialize`, `Type`. Methods: `is_final`, `is_side`, `is_active`, `clocks_run`.
- `Run { state, return_to }`, `Run::new()` (Queued), `Run::apply(RunEvent) -> Result<Run, Refused>`. This is the one transition table. Log each `Refused` (it has `Display`).
- `RunEvent`: `Claim`, `Start`, `PlanReady { gate }`, `PlanApproved`, `PlanRejected`, `BuildDone`, `FixRound`, `Finished`, `PrOpened`, `ChangesRequested`, `FixStarted`, `PrMerged`, `Closed`, `Ask`, `Block`, `Retry`, `BudgetStop`, `Fail`, `Cancel`, `Answered`, `Unblock`, `RetryDue`, `Resume { budget_left }`. Serde: `{"kind": "plan_ready", "gate": true}`.
- `retry_delay(n) -> Duration`, `after_failure(failures, retry) -> RunEvent`, `after_review(blocking, rounds_done, max_rounds) -> Option<RunEvent>`, `budget_level(spent, budget) -> BudgetLevel { Under, Alert, Spent }`.
- `Stopwatch { spent, since }`: `started(now)`, `read(now)`, `follow(state, now)` after each state change, `reset(now)` at each event (stall timer).
- `staged_labels(current, status_map, state) -> Vec<String>`: the ticket labels after a move.
- Constants: `RETRY_BASE`, `RETRY_CAP`, `MAX_ROUNDS`, `BUDGET_ALERT`.

`shipyard_core::workflow`

- `Workflow { id, steps: Vec<Step>, limits: WorkflowLimits }`, `Step` (all REQ-012 fields), `Effort`, `Mode`, `Workspace`, `Gate`, `Action::OpenPr`. Parse with `serde_yaml`: unknown fields are refused.
- `Workflow::check(roles) -> Vec<WorkflowIssue>`. Give `DEFAULT_ROLES` plus the file names of `.shipyard/roles/`. The store maps an issue to a line.
- `Workflow::step(id)`, `Step::max_parallel()`, `Step::source() -> Option<ForEach { step, field }>`.
- `StepState { Pending, Running, Gate, Done, Failed }`, `runnable(wf, states) -> Vec<String>`, `next_children(children, max_parallel) -> Vec<usize>`, `fan_in(children) -> StepState`.
- Schema: `crates/shipyard-core/schema/workflow.schema.json`. A test keeps it equal to the model.

`shipyard_core::question`

- `parse_reply(text, options, free_text) -> Option<Choice>`. `None` is an unclear reply.
- `Question::new(id, question, options, recommended, free_text, spec) -> Result<_, AskError>` checks the `ask_question` shape.
- `Question::reply(comment_id, text)`, `choose(Choice)`, `edit(comment_id)`, `withdraw()`. They return `Outcome { Answered, Unclear, Late, Closed }`. Log `Late` and a `true` edit.
- `QuestionState`, `can_move`, `all_answered(questions)`: send `RunEvent::Answered` only when it is true.
- After each post, call `Mirror::question_posted` (W4 note). `pickup::answers` gives the question of each comment.

`shipyard_core::delivery`

- `kebab`, `branch_name(ty, area, subject)`, `commit_type(WorkKind)`, `is_tool_branch`, `TOOL_PREFIXES`, `conventional(ty, scope, subject)`.
- `base_branch(declared, branches, default) -> Result<String, BaseError::Release>`.
- `pr_labels(existing, ty, changed_paths)`: additions only.
- `PrBody { opening, gate: Vec<GateCheck>, tickets: Vec<TicketLine>, impacts }`, `render()`, `strip_attribution`.
- `Lane` (six, `Lane::ALL`), `PrSignal { ci: Ci, changes_requested, draft }`, `lane(state, pr)`.

### Decisions to confirm

- A workflow without a pull request step ends with `RunEvent::Finished` (`Working` or `SelfReview` to `Done`). Factory REQ-001 now says so.
- `steps` is a list with `id`, not the map in MASTER-PLAN 5.4. The plan says so. MASTER-PLAN is not changed.
- The clocks run only in `Planning`, `Working` and `SelfReview`.
- `Merged` counts as active: a rejected ticket move after the merge can block the run.
- The step to run state mapping (which step is the plan, which is the build) is not in core. The engine decides it.

## Store (`shipyard-store`)

Scope: factory T005 to T007, questions-loop T003, T004, T009, T010, delivery T017 (store part). No new dependency. Legacy sources: `src/lib/raid.ts` and `src-tauri/src/infrastructure/raid.rs` (RAID codec, ids, clarification bullet), agent-compass `core/agents/{scout,worker,reviewer}.md` (role prompts), `src-tauri/skills/STYLE-CONTRACT.md` (style block).

### Public API for the engine worker

`shipyard_store::run_log` (SQLite file in the app data folder, for example `runs.sqlite`)

- `RunLog::open(path)`, `open_memory()`. A layout that this build does not know is an error, never a reset.
- `append(run, step: Option<&str>, kind, &serde_json::Value, ts) -> id`. `ts` is Unix ms from the engine clock: the store never reads a clock. `run` is the ULID of `run:<ulid>` and must not be empty.
- Reads: `run(run)`, `since(id, limit)` (the tail), `last(run, kind)` (use it for the run state after a restart), `runs()`, `cites(target)` (runs whose payload holds the exact string, for `pr:`, `wi:`, `q:` backlinks).
- No update and no delete exist. SQL triggers refuse both. A log event has `id, run, step, kind, payload, ts`.
- `run_log::kind`: `STATE`, `TOOL`, `RUNNER`, `WRITE`, `NOTE`, `PR`. Any other text is allowed. Suggested payloads: `STATE` `{"from","to","event"}`; log each `Refused` and each late answer or edit as `NOTE`.

`shipyard_store::factory_files`

- `seed(root)`: writes the five workflows and seven roles into `.shipyard/workflows/` and `.shipyard/roles/`, per directory, only when the directory is missing. Call it on the first use of a project.
- `load(root, &last: &Loaded) -> Loaded { workflows: BTreeMap<id, Workflow>, roles: BTreeMap<name, Role>, issues: Vec<FileIssue{file, line, message}> }`. An invalid file keeps its version from `last` and adds an issue. Call it again when the watcher fires. `Loaded::role(name)` falls back to the bundled profile.
- `Role { id, description, model, effort, prompt }`. `parse_workflow`, `parse_role`, `default_workflows()`, `default_roles()`.
- Models are tiers `top`, `mid`, `small`. **The engine and `connections` must map each tier to a model of each runner in config.** Nothing maps them yet. A step's `model` and `effort` win over the role profile.
- `feature` runs `grill` (skill `grill-me`), `plan` (`gate: human`, `mode: plan`), `build` (`for_each: plan.tasks`, `max_parallel: 2`, `workspace: worktree`), `review` (`fresh_context`, `max_rounds: 2`), `pr` (`open_pr`). The planner prompt tells the agent to return the list `tasks` in its report. Tool names in `tools:` are the eight MCP tools.

`shipyard_store::automation_file` (extends the sync codec)

- `default_status_map()` (sixteen rows, the plan table), `status_map(&Automation)` (defaults plus the file rows; use it with `run::staged_labels`), `load_automation(root, &last) -> AutomationLoad { automation, issues }`.

`shipyard_store::raid`

- Types `Item` (with `missing`, `flagged()`), `Kind`, `Status`, `RegisterFile`. Codec: `parse_item(path, text)`, `format_item(&Item)`, `new_item(id, raised_at)`, `item_path(id)`, `from_question(&core::Question, raised_at, raised_by, ticket)`, `can_transition`.
- Files: `list_register(root)`, `read(root, id)`, `next_id(files, taken)`, `create(root, item, taken)` (allocates, `create_new`, never overwrites), `save(root, &item)` (existing file only, checks vocabulary and lifecycle), `answer(root, id, text)`. No delete. `taken` holds the ids of the ticket comments (Q-026). Create the file only for a question with a spec ref (REQ-007), and do not commit it.

`shipyard_store::fold`

- `fold_preview(spec_text, &Item) -> Result<Fold { after, edits: Vec<Edit{line, removed, added}> }, FoldError>`. Pure. `specs` REQ-015 writes `after` on a click, then `raid::save` with `Folded`.

`shipyard_store::pr`

- `rows(&Mirror, forge, source)`, `row(...)`, `PrRow { reference, forge, number, title, state, draft, ci, review, head_sha, url, updated }`, `PrRow::signal()` for `delivery::lane`, `pr_ref`, `record(log, run, step, forge, number, ts)`, `pr_of_run(log, run)`, `runs_of(log, forge, number)`. `forge` is the connection id in the ref. `source` is the mirror key.

### Decisions to confirm

- A mapping file with no row for a state keeps the default row (factory REQ-008 scenario "Missing row" changed). A row for a name that is not a run state still keeps the last valid file.
- The run log refuses a change. It does not log the refused attempt (factory REQ-021 scenario said eleven events).

- `questions-loop` fold bullet uses the Legacy form `- Q: ... -> A: ...`. A marker is replaced with its working assumption up to the first `. ` (shortcut in `fold.rs`).
