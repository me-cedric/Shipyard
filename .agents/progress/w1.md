## Spec layout decision

OpenSpec 1.15 `validate --strict` rejects every `## ` section of a delta spec except the delta sections and `## Purpose`.
The compass rule (`spec-flow/references/delta-section.md`) keeps the spec-kit headings at `## `. That fails `--strict`.
Therefore each `spec.md` keeps the spec-kit headings at `### ` level under `## Purpose`, then `## ADDED Requirements`.
Follow-up: align the compass `delta-section` rule with OpenSpec 1.15.

### Run states (factory)

Main path: `Queued`, `Claimed`, `Planning`, `PlanReview`, `Working`, `SelfReview`, `PROpen`, `ChangesRequested`, `Merged`, `Done`.
Side states: `WaitingForAnswer`, `Blocked`, `RetryQueued`, `Paused`, `Failed`, `Cancelled`.
Runs lanes (Factory / Runs): Queued, Working, Needs you, In review, Ready to merge, Done.

### Agent MCP tools (factory, served by `shipyard-mcp`)

`ask_question`, `post_progress`, `handoff`, `message`, `spawn_subtask`, `report`, `read_ticket`, `read_ref`.

### Automation writes (factory owns the switches)

`push`, `pull_request`, `tracker_transition`, `tracker_comment`. Default: all off (Q-002, option 1, working assumption).
A write without its switch becomes an approval in Home / Inbox. One click sends it.
