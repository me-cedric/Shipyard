# W4 progress: sync backend (tick, mirror, claims, hand-off)

Branch: `feat/work/space`. Scope: spec `add-sync`, tasks T001 to T014. Another worker builds the `work` backend in the same worktree. Not pushed.

## Sync backend (`shipyard-core::pickup`, `shipyard-store::{mirror, automation_file}`, `shipyard-engine`)

### Decisions

- Ports, not adapters. The engine has its own traits in `shipyard-engine/src/ports.rs`: `TrackerPort`, `ForgePort`, `Dispatch`. The engine does not depend on `shipyard-trackers` or `shipyard-forges`: those crates change in parallel, and the `Tracker` trait has no write method for the claim stamp. The wiring worker writes two thin wrappers.
- Synchronous. The adapters are sync (`ureq`), so the engine is too. `Engine::run(sleep)` is the loop. A `Clock` trait and `fake::FakeClock` make the tests deterministic. The plan said "async tick": the plan is updated.
- One engine per project: one tracker connection and one optional forge connection. The mirror is one file, keyed by connection id.
- Jitter: a 12-line xorshift in `tick.rs`, up to 20 % of the interval, added to it. No random crate is a direct dependency of the workspace.
- Claim stamp (`q:Q-020`): it follows `writes.tracker_comment` (option 2), not the recommended option 1. A stamp is a tracker write, and the constitution (5.4) and the agent rules need a permission for it. With the switch off, or with a tracker that cannot stamp, the claim is a local row. The engine still reads stamps and yields to a live one of another machine. The spec says so (REQ-009).
- Stamp protocol: the oldest live stamp wins. After a write the machine reads back. A refresh happens every tick. A machine that wakes after a takeover stops its run with `REASON_CLAIM_LOST`. Stale time is 10 minutes (`q:Q-021`, `Config::stale`). The port gives the age of a stamp by the tracker clock, so machine clocks do not matter.
- Events: the compare step writes comment and pull request events to an outbox in the mirror file, in the same transaction as the mirror update. The hand-off step sends them and removes them after `Dispatch::event` returned `Ok`. A crash or a refusal keeps them. This is at-least-once: a crash between the send and the removal sends one event twice.
- Baselines: the comments of a ticket are a baseline at claim time (they are not new, except an answer after a `<!-- shipyard:q Q-NNN -->` marker). The first read of a forge sends events only for the pull requests of runs.
- Pickup reads the ticket again before the claim. Nothing is picked up while the last tracker poll failed. A run with a pull request is not stopped while the forge poll fails.
- Empty status set in the filter means the `Todo` category. The assignee in the file is a team handle. The caller replaces it with the tracker person id or name before it calls the engine.
- `automation.yaml` keys are snake_case: `interval`, `pickup`, `concurrency` (`global`, `per_project`, `per_status`), `status_map` (key: run state name), `writes`. A `null` label turns the label filter off. An unknown key is refused.
- Import does not move the tick cursor, so a closed ticket is never hidden from the next tick.

### Public API

For the wiring worker:

- `shipyard_core::pickup`: `Automation` (+ `validate`, `terminal`), `Filter`, `Limits`, `StateMapping`, `Writes` (+ `stamp_allowed`), `Ticket`, `PullSnapshot`, `SyncEvent`, `ActiveRun`, `AUTOMATION_FILE`, `MIN_INTERVAL`. `Automation`, `Filter`, `Limits`, `StateMapping`, `Writes` derive `specta::Type`. Pure rules: `pickup`, `matches`, `stops`, `changed_tickets`, `diff_pulls`, `question_marker`, `answers`.
- `shipyard_store::automation_file`: `read_automation(root) -> AutomationRead::{Missing, Valid, Invalid}`, `parse_automation`, `render_automation`, `write_automation` (validates first, atomic).
- `shipyard_store::mirror::Mirror`: `open(path)` (use `<data dir>/mirror.sqlite`), `tickets`, `ticket`, `pulls`, `state`. The refs and `wi:` or `pr:` entities read these (REQ-016): call `RefIndex::set_source("mirror:<key>", ...)` after a tick that changed rows.
- `shipyard_engine::tick::{Engine, Config, TickReport, SourceState, backoff}`: `Engine::new(cfg, automation, mirror, tracker, forge, dispatch, clock)`, `with_jitter`, `set_automation`, `tick(force)`, `sync_now()`, `run(sleep)`, `next_due()`, `states()` (sync state per connection), `release(key)`, `mirror()`.
- `shipyard_engine::import`: `Engine::{import_plan, import, adopt, link, unlink}`. `ImportPlan::count()` is the count to show before the confirm.
- `shipyard_engine::{Clock, SystemClock, iso}`.
- Ports to wrap: `TrackerPort` (`list`, `get`, `comments`, `can_stamp`, `stamps`, `write_stamp`, `clear_stamp`) and `ForgePort` (`pulls`, `pull`). The doc comments say what each call returns.

For W6 (factory), implement `shipyard_engine::ports::Dispatch`:

- `kill_switch()`, `active_runs() -> Vec<ActiveRun>` (all projects on this machine; give `pr` once the run has a pull request number; `status` is the ticket status at pickup).
- `start(&StartRequest)`: create a run for a claimed ticket. Return `Ok` only when `active_runs` lists it. The engine releases a claim that no active run holds.
- `stop(run_id, reason)`: the reason (`ticket terminal` or `claim lost to another machine`) goes on the run. A run whose pull request merged is never sent here: it goes to Merged.
- `event(&SyncEvent)`: `Comment { key, comment, answers }` for questions-loop, `Pr(PrEvent)` for delivery, `Tick` for every listener.
- Call `Engine::release(key)` when a run ends, so the claim and the stamp go at once.

### Open

- T014a, T015 to T021 (IPC, entities, UI, i18n, e2e, changelog, final validation) belong to the wiring worker.
- The tracker and forge adapters do not return components, priority or reviews: `Ticket.components` and `Ticket.priority` stay empty, and `PullSnapshot.changes_requested` stays `false`. A filter on component or priority matches nothing until the adapters fill them. The `Tracker` trait has no stamp methods: the wrapper maps `stamps`, `write_stamp`, `clear_stamp` to comments that hold a machine id (needs the tracker write work of the other worker).
- A run that ends while its ticket still matches the filter (transitions off, label kept) is picked up again at the next tick. Factory should move the ticket (a write, so an approval) or the person removes the label.
- `per_status` counts the ticket status at pickup, not the status after the factory moves the ticket.
- Webhook relay, per-connection interval and a "running" state of a connection are not built. `states()` gives last good poll, failure count and error.
- Pickup takes at most the free slots, then tries each. A lost claim leaves a slot empty until the next tick.
- Not run: any real adapter, a desktop session, the sync action in the status bar (Q-041).

## Work backend (`shipyard-core::work`, `shipyard-store::{work, seal, excel}`, `shipyard-trackers::work`)

Scope: spec `add-work`, tasks T001 to T010. Not pushed. No IPC command, no frontend, no changelog entry (T011 and later are the wiring worker's).

### Decisions

- Member: `handle` (the `member:<handle>` slug) plus `trackers` (accounts in the trackers). A handle or an account that two members share refuses the file. `Team::resolve(id)` finds a member by either, so sync resolves the tracker assignee through it. Capacity is days a week.
- One day rate: the mean rate of the members of a role is the rate of the role (Q-060, option 1). Cost is days times that rate. Price is cost times (1 + margin rate of the sheet). A task with no rated role costs nothing and its role is listed in `Totals::unrated`.
- Files: `.shipyard/team.yaml`, `docs/costing/<slug>.yaml`, `docs/planning/{plan,calendar}.yaml`, `docs/time/<handle>/<yyyy-mm>.yaml`. Every type refuses an unknown key, so a total or a computed date has no key to live in. A task has `days` or `percent`, never both (percent is a share of the build days; a task marked `other` is not build).
- Seal: one line `SHIPYARD-SEALED-v1:<salt>:<nonce>:<ct>` (AES-256-GCM, PBKDF2 600,000 rounds, `ring`). A whole sheet is sealed, and in the team file only the `dayRate` value. A locked team (sealed rate, no passphrase) reads with no rates and `Team::locked`. A write of a locked team is refused. ADR 0011 (status proposed) records the Excel crates and `ring`.
- Gantt: members take capacity in the order of the decision file. A task goes to the member of its role that finishes first, or to the chosen member. No predecessor links. A task with no member runs one day for each day of effort. The spread uses the role rate, so it sums to the summary.
- Excel: worksheet `Estimate` with columns found by header text, `Settings` and `Summary` (values). `preview` writes nothing and lists each refused row with its Excel row number. `replace_sheet` needs `confirmed = true` and writes through a temporary file. A workbook with several `Scope` values reads one lot (`scope` argument), the preview lists the others.
- Tracker writes: `shipyard-http` gains `PUT` and `PATCH` (`Request::write`). Built for Jira Cloud, Jira Data Center and GitHub Issues. GitLab, Azure DevOps and Linear answer `TrackerError::Config` and send nothing. `TrackerError` gains `Refused` (the tracker said no) and `Lost` (a write left and its answer did not return).
- Worklog: `send_worklog` needs a `Click` and looks up the mark of the entry in the tracker before it sends. A failed lookup sends nothing. A found mark returns `Sent::AlreadyThere` with the receipt to store.
- Apply: a row matches a ticket by the row ref in a label (Q-033, option 1). A create looks the label up in the tracker first. Apply never writes the status or the assignee.

## Tracker writes, comments and markers (`shipyard-trackers`, `shipyard-http`)

Scope: spec `add-work` T010a and T010b, input for `add-sync` REQ-009 and `add-questions-loop` REQ-006 and REQ-009. Not pushed. No live tracker: every test uses a fake `Http` and recorded-style JSON in `crates/shipyard-trackers/tests/fixtures`.

### Decisions

- Comment calls live on `TrackerWrite`. Marker kind `claim` is for the stamp, `q` for a question.
- One canonical marker: `<!-- shipyard:KIND ARG -->`. `KIND` is `[a-z]+`. `ARG` is one token of `[A-Za-z0-9._-]`. The caller writes and reads only this form.
- Wire form. GitHub and GitLab keep the raw Markdown, so the canonical form goes out as it is (the page hides it). Jira (wiki), Azure DevOps (HTML) and Linear (Markdown) get the plain token `(shipyard:KIND ARG)`: it has no `<`, `>` or `--`, so no conversion changes it. It shows as small text. The adapter maps both ways on every write and every read, also on `Tracker::comments`.
- Not verified on a live tracker: that GitHub and GitLab hide the comment, that Jira Cloud and Azure keep the token. The tests simulate the conversions that the products document (Jira Cloud `--` to a dash, Azure `div` wrap and HTML comment removal).
- `Tracker::comments` now follows every page (cap: 50 pages). Before, it read the first 100.
- Edit and delete: a 403 is `Refused` ("only the author can change this comment"). A comment id goes in a URL only as digits.
- A stamp refresh: `Comment` has no edited time, so refresh is delete then add. The age of a stamp is `created`.
- HTTP: `Method::Delete`, `Request::delete`, `FakeHttp::delete`. A request keeps its own `Content-Type` (Azure uses `application/json-patch+json`).
- Azure comments use `api-version=7.1-preview.4`, the version that the comments API has in 7.1. The read call used `7.1` before.
- GitLab time uses GraphQL (`timelogCreate`, `Issue.timelogs`, GitLab 15.x), because REST has no list of entries and REQ-023 needs one. `reduce_remaining` changes nothing there.
- Azure DevOps: no worklog (`Unsupported`): it keeps a Completed Work total, not entries, so no mark. The flag `time_tracking` stays on for the estimate. Azure picks the story type from the project (`User Story`, `Product Backlog Item`, `Requirement`, `Issue`, `Task`). A story type without `OriginalEstimate` is sent again with no estimate, and the result says `Estimate` was skipped. A tag write guards the revision.
- Linear: the issue UUID comes from a lookup before each mutation. A missing label is created (team label, or the workspace one). No worklog. A day estimate has no field: skipped.
- Jira Data Center: `GET /field` once for each connection gives `Epic Link` (parent of a story) and `Epic Name` (set on an epic). Jira Cloud is unchanged: no field call, no epic name.

- `work::TrackerWrite`: `comments_page(&self, key: &str, cursor: Option<&str>) -> Result<Page<Comment>, TrackerError>`, `add_comment(&self, key: &str, body: &str) -> Result<String, TrackerError>`, `edit_comment(&self, key: &str, id: &str, body: &str) -> Result<(), TrackerError>`, `delete_comment(&self, key: &str, id: &str) -> Result<(), TrackerError>`.

## Sync wiring: host, adapters, IPC, UI (`add-sync` T014a to T021)

Scope: `shipyard-app` (`sync.rs`, `commands/sync.rs`, `connections.rs`), `src/features/sync/`, `src/lib/sync/`, two molecules in `src/ui/`, the status bar sync action, the mock, `e2e/sync.spec.ts`, the changelogs. Not pushed.

### Decisions

- Adapters: `TrackerAdapter` and `ForgeAdapter` build the connection adapter for each call (`Connections::tracker_write(id)`, `Connections::forge(id)`). A new secret or address applies at once. A removed connection is a failed poll with a reason.
- Tracker list: with `since` it returns closed tickets too (a run must see one close). Without it, open tickets only (the `Done` category is dropped).
- Forge list: with `since` it asks for all states, and keeps an open pull request (its CI can change with no update time) or a pull request updated since. A page with an old item ends the walk (not Azure DevOps). Each open pull request costs one CI request.
- Claim stamp: a comment with the hidden marker `<!-- shipyard:claim <machine> -->`. It is on when `writes.tracker_comment` is on and the tracker has comments. Age is the creation time against this machine's clock. A stamp is written again only when it is older than 3 minutes (add, then delete the old one). `comments()` leaves stamps out, so `questions-loop` never reads one. The machine id is `m-<nanos>-<pid>` in `<app data>/machine-id`.
- Host: `SyncHost` (in `AppState.sync`) keeps one `Running` engine for each project that names a tracker connection. The loop is on its own thread and takes the engine lock for each tick. `Engine::run` is not used: it holds the engine for the whole loop, so the sync action could not tick. Tests build the host with `background = false` and tick by hand.
- The engine starts at app start, at project open, switch and save of `project.yaml`, at each `sync_state` and `sync_now`, and at the save of the automation file. An invalid automation file stops the engine, so no pickup runs on rules that nobody can read.
- Placeholder `Dispatch`: a started run is a note `would start a run on <key>` and counts as an active run (claims and limits stay true). `stop` removes it. It keeps the global kill switch (`set_kill_switch`). No UI sets the switch: it belongs to `factory` (REQ-024).
- Views read the mirror: each command opens its own `Mirror` on `mirror.sqlite`. No view calls a tracker.
- `wi:` and `pr:` resolve in `refs_resolve` from the mirror, not from the ref index.
- One event: `sync-tick`, after each tick and each change of the mirror (import, adopt, link, save). The views read their queries again.
- The sync action runs a tick, then the git pull. A failed tick does not skip the pull. The failed polls show in the status bar and in the notification centre.
- Where: Work / Backlog (import after a count, adopt by key, link to a local ref, filters), Settings / Connections (state row of each tracker and forge connection of the active project), Settings / Project (Automation group).
- Mock: `mock-sync.ts` holds a fake tracker with 12 tickets. The mirror starts empty. Only a tick, an import or an adopt fills it.

### Public API

- `shipyard_app::sync`: `SyncHost::{new, on_change, changed, mirror, running, apply, states}`, `Plan`, `Running::{tick, set_automation, with, plan_import, import, plan}`, `TrackerAdapter`, `ForgeAdapter`, `Placeholder::{set_kill_switch, notes}`, `repo_slug`, `epoch_secs`.
- For `factory` (W6): implement `shipyard_engine::ports::Dispatch`, then replace `SyncHost.dispatch` (today `Arc<Placeholder>`) with it. Call `Running::with(|e| e.release(key))` when a run ends.
- IPC: `sync_state`, `sync_now`, `sync_automation_get`, `sync_automation_save`, `sync_items`, `sync_import_plan`, `sync_import_confirm`, `sync_adopt`, `sync_link`, `sync_unlink`.

### Open

- The tracker container has no setting. GitHub and GitLab use the origin repository. The other trackers use the key of `project.yaml`, which must then be the Jira project key, the Azure DevOps project or the Linear team. A wrong key shows as a failed poll.
- The assignee of the filter is compared with the tracker person id or name. The resolution through `team.yaml` handles (REQ-006) is not done: a filter that holds several accounts is needed.
- The claim stamp, the refresh and the stale takeover are tested with fake trackers only. Not verified on a live tracker. The age uses the local clock.
- `ForgePort` reads no review, so `changes_requested` stays false. No adapter fills components or priority.
- The engine of a project that is not active keeps running until the app quits. No UI stops it.
- Not run: a desktop session, a live tracker or forge.
