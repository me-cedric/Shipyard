## Items

1. Clone from an account: the clone dialog (`src/features/projects/clone-dialog.tsx`, and the first-run clone in `first-run.tsx`) takes a link only. Add a picker: choose a code host account (a GitHub or GitLab connection, or sign in with the browser from the dialog), list its repositories with search and owner or group filter (the `Forge::list_repos` call exists in `crates/shipyard-forges/src/lib.rs`), pick one, pick the folder, clone. Keep the link field as the other way.
2. Resizable panels: the sidebar, the list and detail split, the inspector, the assistant panel and the drawers can be resized with the mouse and the keyboard, and keep their size per person.

## Stage 0: first-use fixes found by the owner in the installed app (do first)

- Being worked on now: one GitHub or GitLab sign-in serves both roles and links the code host; a stale sync failure clears on a new secret or a passed test; the Pull requests empty state tells "no code host" from "no pull request"; a Copy button on the sign-in code; Quality checks that fit the project (login shell PATH, the failure reason, gates, then compass commands, then stack detection, and "Set up checks").
- Follow-ups of the sign-in fix: the GitLab twin connection copies the secret, but GitLab refresh tokens are single-use, so after one role refreshes the other needs a new sign-in (`serve_twin` in `crates/shipyard-app/src/connections.rs`): make both roles read one shared credential entry. The pull request mirror needs an issue tracker on the project: a project with only a code host gets no pull request sync.
- Work / Time on a project with no `.shipyard/team.yaml` (StoryArc) shows a raw error: "cannot resolve the member: set `user` on the tracker connection to a tracker account of the team, or name the member" (`crates/shipyard-app/src/work.rs`). It names a config field, says "tracker", bypasses the error contract, and the member list is empty. Fix: the browser sign-in and a token test save the account login on the connection (`user`) by themselves; the person is resolved from that login or from the git e-mail; with no team, Time shows one empty state whose action adds the signed-in person to the team (name, handle and issue tracker login filled in); the member choice defaults to the person; any remaining failure goes through the error contract in plain words with one action.
