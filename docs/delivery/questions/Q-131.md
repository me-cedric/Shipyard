# Which GitLab tiers and versions expose the MCP server, and at which address?
The gitlab.com application allows the `mcp` scope. The build must know if the GitLab MCP server needs a paid tier or GitLab Duo, the first GitLab version that has it on a self-hosted server, and its address (for example `https://<host>/api/v4/mcp`). The answer decides when the switch shows.

Options:
1. Show the switch only on hosts where a probe of the address answers.
2. Show the switch on every GitLab host and let Test report a missing server.

## Answer

Source: GitLab docs, "GitLab MCP server" (docs.gitlab.com/user/model_context_protocol/mcp_server/), read 2026-10-31.

- Tiers: Free, Premium and Ultimate. Offerings: GitLab.com, GitLab Self-Managed and GitLab Dedicated. GitLab Duo is not required for the core toolsets.
- Versions: experiment in 18.3, beta in 18.6, generally available in 19.5. No feature flag remains.
- Address: `https://<host>/api/v4/mcp` (GitLab.com: `https://gitlab.com/api/v4/mcp`).
- Authentication: an OAuth access token that holds the `mcp` scope, or a fine-grained personal access token. A legacy personal access token, a project token and a group token get `403 insufficient_scope`. The `api` scope alone does not open the endpoint.
- An administrator must allow MCP server access (the top-level group on GitLab.com, the instance on Self-Managed).

Chosen option: 2. The switch shows on every GitLab connection whose granted scopes hold `mcp`. Test reports a missing server or a refused token in plain words. A host that is older than the first version, or that blocks MCP access, answers Test with an error.
