# Which Legacy JSON keys does a save keep, and in which order?
A save merges into the existing JSON file. Keys that Shipyard does not own (groups, macro sizes, the plan, windows, brick names) stay. The JSON keys come out sorted, because the workspace does not use the `preserve_order` feature of serde_json. A flow takes its Shipyard id from its place in the file. A Legacy sheet is not sealed and takes no Excel import. The personas file is read for roles only. A custom costing or planning folder in the Legacy registry is not used: the folders stay docs/costing and docs/planning.

Options:
1. Sorted keys, merge on save. (chosen)
2. Enable `preserve_order` so the key order stays. Run the tests of each crate first.
3. Add costing, planning and personas keys to the project file paths.
