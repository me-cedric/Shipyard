# Who builds and tests the Windows named pipe of the MCP relay?
The relay talks to the proxy over a Unix socket on macOS and Linux. On Windows it needs a named pipe. This Mac cannot build or run Windows code, so the pipe is not written: untested Windows code is a risk. On Windows the relay starts the server itself, as before. T012c stays open.

Options:
1. Leave T012c open. Write the pipe in a session on a Windows machine, or in a Windows CI job, with its test. (recommended)
2. Write the pipe now, guarded by `#[cfg(windows)]`, and test it only when a Windows build exists.
3. Drop the Windows proxy: the relay always starts its own server on Windows, and the spec says so.

## Answer
Leave T012c open. Write the pipe in a session on a Windows machine, or in a Windows CI job, with its test.
