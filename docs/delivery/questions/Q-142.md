# What happens on a rename or delete of a workflow in use?
The project file names a default workflow, a ticket names one with the label `wf:<id>`, and a live run reads its workflow at each step.

Options:
1. Refuse to rename or delete the default workflow and a workflow that a live run uses. A ticket with the label of an old id gets the error `no workflow <id>` when its run starts. (recommended, built)
2. Rename also changes the default workflow in `.shipyard/project.yaml` and the labels of the tickets.
