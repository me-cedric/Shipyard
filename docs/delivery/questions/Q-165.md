# Can a role hide an area, and can the team change the table of the roles?
The flat rights turn controls off but never hide a view. The owner wants a level per area for each role, a table that the team can change, and more than one role for a person.

Options:
1. Levels per area (`none`, `read`, `write`) for each role, a `roles:` block in the team file that changes the defaults, several roles per member with the highest level in each area. The level `none` hides the area, except Settings for an admin. (recommended)
2. Keep the flat rights. A right turns a control off and never hides a view.

## Answer
Option 1, the request of the owner (2026-11-06). The areas are `work`, `specs`, `design`, `knowledge`, `code`, `runs`, `settings` and `costs`. The actions `code.merge` and `runs.approve` stay switches, valid only with `write` on their area. The ten rights of the backend check map to the levels. The level `none` hides the space in the views and refuses the read tools of the Shipyard MCP server for that area. The read commands of the app are not gated: the files are on the disk of the person. Settings is never `none` for an admin, and the last admin cannot remove their own settings write.
