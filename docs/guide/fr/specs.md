# Spécifications

Les Spécifications disent ce que le produit doit faire. Un changement commence comme une proposition. Quand l'équipe est d'accord, la proposition entre dans les capacités.

## Propositions

Propositions liste les changements en cours, avec l'état de chaque partie : manquante, brouillon ou terminée.

1. Cliquez sur Nouvelle proposition. Donnez-lui un titre simple. L'application fait l'identifiant à partir du titre.
2. Remplissez chaque partie. Une vue formulaire montre les parties. Une vue en texte brut existe aussi.
3. Cliquez sur Valider. Chaque problème s'affiche sur sa partie, avec sa ligne.
4. Suivez l'étape suivante que l'application montre : par exemple, découper le travail en tickets.

Pour partir d'un élément de l'outil de suivi des tickets, cliquez sur Depuis un ticket et choisissez le ticket. L'application crée le changement avec le titre du ticket, met le texte du ticket dans la proposition et vous place sur la branche specs/<id>, pour que le changement reste à part du code. Cliquez ensuite sur Confier à un agent pour qu'une exécution d'agent prenne le ticket.

Un changement prend son titre dans le premier titre de sa proposition. Donnez un titre simple à chaque proposition. L'identifiant reste le nom du dossier.

## Capacités

Capacités liste ce que le produit fait aujourd'hui, avec les exigences de chaque capacité.

## Questions

Questions est le registre des points ouverts : risques, hypothèses, problèmes, dépendances et questions.

- Filtrez par type, état et responsable.
- Cliquez sur Nouvelle question pour en ajouter une. Choisissez le responsable dans l'équipe.
- Après votre réponse à une question d'une spécification, un clic copie la réponse dans la spécification.

## Plans de test

Plans de test liste les scénarios de test. Chaque scénario nomme les exigences qu'il vérifie.

## Constitution

Constitution contient les règles du projet que chaque changement doit suivre.
