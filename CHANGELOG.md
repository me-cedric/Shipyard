# Changelog

## [0.1.0]

### Added

- Desktop app skeleton on Tauri v2 with a Rust workspace of 10 crates.
- Sidebar with the seven spaces and Settings, each space with its tabs.
- Command palette, inspector panel and status bar with sync and commit.
- Light, dark and system themes, English and French, and a home per role.
- Design system with tokens, components and a gallery in the dev build.
- First run to open a local folder, clone a repository or create a project, and a project switcher in the sidebar that shows the state of each working copy.
- Settings / Project for paths and the default workflow, with per-project overrides of the theme, the density, the contrast and the accent colour.
- Settings / Health with one fix for each finding, and a health dot in the status bar.
- Reference index: backlinks grouped by kind in the inspector, and search by ref or title in the command palette.
- Preferences, language and the last view of each project now live in the app data folder.
- Settings / Connections to add, edit, test and remove tracker and forge connections (Jira, GitHub, GitLab, Azure DevOps, Linear), with the capability flags of each tracker, write-only secrets kept in the system keychain, and the repository list of a forge with a mark on each repository you cannot push to.
- Code space with Changes (folder tree, staged and unstaged diffs, stage, unstage, discard after a confirmation, stash, conflict blocks), History and Branches, a working branch selector in the header, one commit action in the status bar, a sync action that updates the working branch, and a notice when a colleague pushes. A clone uses the saved token of the forge connection with the same host.
- Settings / Connections now also lists MCP servers (catalogue and custom, start, stop, Start all, live state, missing dependencies with an install action), the agent runners detected on this machine, and model providers with a test and a model list. Keys and secret fields stay write-only. The app keeps started servers open for agents through a relay and stops them when it quits.
- Notification centre with a bell in the status bar and toasts, a system notification for events that need you while the window is in the background, a native menu in your language that runs the same actions as the palette, and an update check that only tells you when a newer version exists. The release address is set in Settings / Me.
- Context menus on files, commits, refs and connections, with the actions of the row, from the secondary click or the keyboard.
- Settings / Project can record the tracker and forge connection of a project in `.shipyard/project.yaml`, by id only.
- Removing a connection now lists every registered project that uses it, and waits for the list. Changing the host of a connection clears its saved secret. A health fix writes only the content you previewed.
- Work / Backlog shows the tickets of the project tracker from a local mirror that a tick keeps current, with an import after a count, adopt by key and link to a local ref. The sync action in the status bar now runs a tick, then updates the working branch. Each tracker and forge connection shows its sync state (idle, running, failed) with the last good time, and a failed poll keeps the last mirror. Settings / Project has an Automation group for the interval (30 s at least), the pickup filter, the concurrency, the status mapping and the four write switches, all off by default.
- Work / Backlog now groups the tickets by status with a count, filters by status, assignee, label and run state, shows a mark on each ticket that this machine claimed, and opens a ticket in the inspector. Work / Board shows one column for each status: drag a card, or press Shift with Left or Right, to send the transition. A refused move returns the card and shows the reason.
- Work / Team lists the members of `.shipyard/team.yaml` and edits them in the inspector (role, capacity, skills, day rate, availability and absences). A duplicate handle is refused and the last valid team stays. A ticket in the inspector lists the members ranked by skill and free capacity, assigns one on a click, and marks the ticket for the agent. An item that is assigned to you and marked shows as eligible for pickup.
- Work / Estimates shows one sheet for each lot in four views (backlog, summary, monthly spread, portfolio), with price, cost and margin computed from the day rates and never stored. Edit a task in the inspector next to the estimate of its ticket, seal all sheets and day rates with a passphrase that stays in memory, and import or export Excel with a preview that lists each refused row before anything is replaced.
- Work / Plan draws a Gantt from a sheet, the team and a calendar of working days and holidays, with a today marker. Move a bar with the keyboard or the pointer to fix its start, and choose a member or the order in the inspector. Only these decisions are stored in the repository, never a computed date.
- Work / Time lists the time entries of one member and month by state (to send, in the tracker, only in the tracker). Add an entry with a day, a duration and a note, and send it to the tracker worklog with one click, with the choice to reduce the remaining estimate. A lost answer never sends twice: fetch the tracker time and store the receipt. A difference of duration is flagged and left as it is.
- Apply from Work / Plan shows the epics and stories to create or update, then writes them to the tracker after one click, with the result of each row. A failed row keeps the rows already written, and a second apply creates no duplicate. A ref in the inspector can also become one work item after one click.
- Design space: Diagrams (Excalidraw and Mermaid to edit, draw.io and BPMN to view and open in another app), Architecture with a live LikeC4 render, Decisions to write an ADR and accept or reject it with a comment, API with a read view by tag and a try panel, Data with the tables and relations of a DBML model, Flows with a filtered table of network flows, and Screens with their design files and the design doc. Each artifact has a ref with a copy action and its backlinks in the inspector, and a save never replaces a file that changed on disk without asking.
- Specs space: Changes with the status of each artifact, strict validation with each finding on its line, and the open markers linked to their questions; Capabilities with the requirements and their backlinks; the Questions register with filters and the fold of an answer into its spec; Test plans in Gherkin with syntax errors and the requirements that no scenario covers; and the Constitution. Split a change into epics and stories, review them, and apply them to the tracker with one click. A second apply creates no duplicate.
- Home / Inbox shows what needs you, in groups with a count: questions of the agents with numbered options (pick with a digit, send with Enter, preview the fold of a spec question), approvals that name the exact write and send it with one click, plans to approve or reject with a note, and messages. Each new item adds one notification.
- Factory space: Runs in six lanes with a count and a card per run, with the pull request, CI and review state; a run view with the workflow graph and the live state of each step, the event tail, the diff, the cost and the kill switch; Workflows to edit the workflow and role files with each error on its line; Agents map; Sessions with the global kill switch; and Usage with spend against the budgets per run, day and member. A budget per day or per member pauses a run at 100 % and alerts at 80 %.
- Assistant panel in every space (Mod+J): threads per project, each with its own runner, model and draft; ask, plan and agent modes, with agent mode in a worktree of its own; the context of the view and added refs; Send to factory and Explain with refs that open.

## [0.0.1]

### Added

- Project plan, constitution and first architecture decisions.
- Sealing the sheets and day rates now asks for the passphrase twice and seals nothing when the two differ. Send in Work / Time is disabled while an entry goes to the tracker, and the same entry never goes twice, even from two clicks. Today, the start of the plan and the default day of a time entry now follow your time zone and not UTC.
- Each project now keeps its own sync cursor and claims for its tracker container, so two projects on one connection no longer mix. Only the open project polls, a cut-off poll no longer skips unread tickets, and an import never overwrites a newer ticket. A claim stamp counts only from your own account and ages by the clock of the tracker. The browser preview opens a demo project with a tracker, so every space is reachable.
