# Changelog

## [0.1.0]
- Each run has its own address and every link to a run opens it; the run page has a summary that stays in view (ticket, state, step, cost, time, tool and pull request), one action for the state (Answer, Approve plan, Unblock, Resume, Open pull request, or Start again for a failed or cancelled run), what needs you under it, and three tabs (Activity, Changes, Workflow) kept in the address; the stop is one word, Stop, in the summary menu; diagrams fit and pan in their frame, and the wheel scrolls the page unless you zoom, pan sideways or hold Shift; a program that ends names itself with its exit code and the end of its output.
- The motion preference now stops every animation (numbers, graphs, section scroll and icons), toasts slide in and out, loaded content fades in under its page header, a removed row leaves smoothly and the focus moves to the next row, and the sidebar and the inspector move on a spring while a resize by drag stays immediate.
- Every tab has a header with its icon, one loading pattern and one empty pattern replace the bare text and the ad hoc skeletons, Agents and rules, Extensions and Health have a section list, the inner tab rows have a sliding mark, and the team rights tables, the Work / Team members table and the learning paths table use the shared table (their cells wrap, and a cut header shows its full name on hover).
- The top bar and the pages hold less: one Activity button (needs you, runs and sessions, each with its stop) replaces three counters, the account menu holds Settings / Me, the theme, the manual, the shortcuts, what is new and the tour, Ask is one split button with the canned prompts behind its arrow, Sync shows ahead and behind, the status bar shows the changed files beside Commit, Terminal and Manual are no longer tabs (their addresses and shortcuts stay), each tab has an icon, and the Home tiles are gone: the number of my items, the spend of today with its 14-day trend and the live runs sit in the headings of Today.
- One Get started checklist of eleven items replaces the earlier Get started and Setup cards, and its done items link to their pages; the tour opens once after the first project; every space with no project shows one page with three ways to open (a folder, a clone, a new project), and the open error shows there; the empty Runs and Backlog pages name the missing step (an AI tool, an issue tracker); the glossary explains issue tracker, code host, AI tool, model, spec, decision, run and pull request on hover and keyboard focus, with a link to the manual.
- A run no longer stays stuck: it fixes blocking findings, red checks, conflicts and empty branches in capped fix rounds, and a stop (a cap, the same failure twice, a spent budget or no answer) writes its cause, last lines, what it tried and the action on the ticket and in the Runs banner, where Unblock, a team reply on the ticket or Close as done moves it on; an ended run no longer restarts by itself.
- Resume takes the limits that the workflow has now, so a budget that you removed no longer stops a run, and Resume with an empty amount works again.
- The app starts on any Mac: libgit2 and OpenSSL are built into it, not taken from Homebrew; the README shows the current screens and how to install a release.
- Work / Team edits the role table: each role shows Hidden, Read or Read and write in each area with Merge and Approve, Edit turns the cells into controls (Save, Cancel and Reset to defaults), a member can have several roles with the levels that result, and Work / Time edits and deletes an entry, with the sync state after the change.
- Team rights work by area: each role has none, read or write in Work, Specs, Design, Knowledge, Code, Runs, Settings and Costs, a member can have several roles (the highest level wins), and a `roles:` block in `.shipyard/team.yaml` changes the table for the team. An area at none leaves the sidebar, the tabs and the palette, its pages show No access, and the Shipyard MCP server refuses its read tools; Settings stays for an admin, and the last admin keeps the admin flag.
- Work / Time sends an entry to the issue tracker when you save it (when the issue tracker has time tracking), keeps the worklog id, changes or deletes the worklog with the entry, and Read the month imports your worklogs made in the issue tracker without doubling the ones Shipyard sent; each entry shows whether it is synced, and why not; the Ticket field is wide and its list shows the full key and the title.
- Every Settings page has one content width and one control column: the fields, selects and switches of all sections line up on the right, and Auto-commit, Agent review and Public holidays sit in the Project section.
- Code / Local changes shows a picture of an image file (the old and the new one side by side when it changed) and one line with its kind and size when a file has no preview; Index in Knowledge / Graph tells you how many nodes it found, or why it failed.
- Knowledge / Graph shows the code graph again: it reads the text table that newer codebase-memory servers return; the cost of a Claude Code run now moves while it works, from list prices per message, and the final total corrects it.
- On the run page, a session opens in the terminal only when its folder and its Claude Code session still exist, and Follow shows a live chat: the Markdown text of the AI tool, one row for each tool call with its result behind a disclosure, questions, reports and notes as cards, and the raw event behind Details.
- A run started before team rights acts for the person of this machine, and the writes that wait go out by themselves once the switches and the rights allow them; Allow notifications shows the macOS prompt again (the app is signed as a whole), and says why when macOS refuses.
- Each step of the tour that maps to a setting now shows its state and one action (new project, AI tool, models, issue tracker, code host, team), and a Setup card on Home / Today and a Setup section in Settings / Me list the same items until each is done.
- Team rights: `.shipyard/team.yaml` gives each member e-mails, one of nine roles (product owner, project manager, architect, tech lead, business analyst, developer, tester, designer, viewer), an admin flag and optional rights changes; ten rights (`work.edit`, `specs.edit`, `design.edit`, `knowledge.edit`, `code.write`, `code.merge`, `runs.start`, `runs.approve`, `project.settings`, `costs.view`) are checked in the backend for each write of the app and of the Shipyard MCP server, and read from the default branch; a person who is not in a team that has an admin reads each page and changes nothing; a project with no admin gives every right, and Health names the missing admin. A control without its right is off and its tooltip names the right and your role. Each role opens on its first tab, shows the panels of its job on Home / Today and gets its own Inbox, with Everyone one click away. Work / Team sets up the team (members, roles with their rights, admin, e-mails), warns when you are unknown or when the file differs from the default branch, lets an unknown person ask to join with a pull request on the team file, moves the roles of this machine into the file, and shows the audit log; a run acts for the member who started it. Settings / Project no longer holds roles, page modes or hidden spaces.
- Shipyard speaks German and Spanish too: Settings / Me and the palette switch between English, French, German and Spanish, and the assistant prompts follow. Settings / Me imports a language file (JSON: a code, a name and the texts) with a list of its faults or the number of translated texts before Add, exports every English text as the start of a new language, marks the texts that a language file does not translate yet, and removes an imported language; a missing text shows in English; a plugin can ship languages that go to the language library after the review. The start page of the manual is in German and Spanish, and another page shows in English.
- New project opens a creator with five steps (Project, Brief, Team, Remote, Start) in Home / Projects and in the first run: a stack preset (Node, Rust, Python, Java, Go, Other) sets the gates and the ignore rules, the brief goes to `docs/brief.md`, the team goes to `.shipyard/team.yaml`, and the remote is local only, an existing address or a new private repository on GitHub or GitLab; the start step previews each file, and Create writes them and makes the first commit; the start is a run of the bundled `bootstrap` workflow, starter issues (one for each scope line, created only on Create issues) or later.
- Settings / Project and the creator set the docs language and the pull request language (`languages` in the project file): each agent brief says them, the pull request text follows the pull request language in English or French, and code, comments and commit messages stay in English.
- A GitHub or GitLab issue is no longer sent a status it cannot take, so a run no longer fails on it; plan steps no longer lose a turn writing a plan file; a paused run takes a message for its agents next to Resume; the Runs count skips replaced runs; the notice of a stopped run says why; Close as done removes the run worktrees; the Graph Index server stays in the MCP settings.
- Unblock now moves a blocked pull request step on: a branch with no change starts one fix round with your message, and Close as done ends the run when the work is already on the base; a rebase conflict starts one fix round where an agent rebases the run branch in the run worktree and resolves the files; a pull request closed without a merge gets a new pull request (with a message, a fix round first).
- Factory / Sessions lists the AI tool sessions of the run units (Active and Previous, with the start time) and a click opens the run page at the unit; the run page lists the units with Follow (their live events) and Open in terminal (`claude --resume` in the folder of the unit, off while the unit runs).
- Markdown editors (documents, decisions, specs, the handbook) colour headings, lists, inline code, links and refs, and the workflow text editor colours YAML; Design / API reads the Shipyard MCP contract again; the menu bar panel's Stop button says only Stop.
- A blocked run takes a message for its agents next to Unblock (Enter sends it); when two tasks of a run change the same file, the second task runs again on top of the first instead of blocking the run, and only a second conflict blocks it; an unblock after the review fix rounds are spent starts one more fix round instead of the same review.
- The Mermaid editor of Design / Diagrams colours keywords, arrows, strings and comments, and so do `mermaid` blocks and `.mmd` files; a blocked run says why on its page; after Shipyard restarts, a paused step continues instead of stopping on an empty prompt; the events of a run start collapsed.
- The sidebar toggle in the top bar has its own icon, a window with its left panel, so it no longer looks like the Work space.
- A run has no budget unless its workflow sets `budget_usd`: the templates set none, a run then shows only its cost, and the day, member and token budgets still stop it.
- Plan review shows the plan (its summary and tasks) on the run page above Approve and Reject, and Home / Needs you shows its first lines with Open plan; Start again on a failed run opens the new run, and the older run of the same ticket leaves the board and Needs you.
- A short tour of six steps opens at the first launch: the loop, open a project, connect the issue tracker and the code host, choose the AI tool, the permissions, and the first run on a ticket; Close ends it, the arrow keys turn the steps, the last step opens the manual, and Help, the palette and Settings / Me replay it. - New projects let agents move tickets, set labels, comment, push the run branch and open draft pull requests with no click; a force push and a merge still wait for you, and each switch can be turned off in Settings / Project.
